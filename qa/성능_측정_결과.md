# 성능 측정 결과 리포트

> 작성: 이상민 (QA) · 측정 환경: Docker Compose 단일 호스트, 카메라 2~3대

## 1. 측정 항목 및 목표
| 항목 | 목표 | 측정 방법 |
|---|---|---|
| 실시간 스트리밍 지연 | ≤ 0.5초 | WebRTC stats / 화면-실물 비교 |
| 다중 카메라 동시 스트리밍 | 4채널 안정 | 프레임 드랍 관측 |
| 녹화 CPU 사용률 | 저부하 | `docker stats` |
| 24h 녹화 누락 | 0 구간 | `ffprobe` 세그먼트 검사 |
| PTZ 응답 시간 | ≤ 1초 | 명령-반응 스톱워치 |

## 2. 측정 결과 요약
| 항목 | 결과 | 판정 |
|---|---|---|
| WebRTC 지연 | 0.3~0.5초 | ✅ 달성 |
| 동시 스트리밍 | 4채널 프레임 드랍 미관측 | ✅ |
| 녹화 CPU | codec copy로 채널당 한 자릿수 % | ✅ |
| 24h 녹화 누락 | 누락 구간 없음 | ✅ |
| PTZ 응답 | 약 0.5~1초 | ✅ |

## 3. 핵심 관찰
- **codec copy(무트랜스코딩)** 채택으로 녹화 CPU 부하가 크게 낮음 → 동일 호스트에서
  실시간 스트리밍과 녹화 병행 시에도 여유.
- **WebRTC(WHEP)** 경로가 HLS 대비 지연이 현저히 낮아 실시간 관제 목표(0.5초) 달성.
- HLS는 탐색 가능한 녹화 재생에 적합 → 용도 분리 설계가 성능 측면에서도 타당.

## 4. 부하 시 주의사항
- 채널 수 증가 시 네트워크 대역폭이 1차 병목 → PoE 스위치/업링크 점검 필요.
- 브라우저 탭당 디코딩 비용 존재 → 그리드 뷰에서 과도한 동시 채널은 클라이언트 측 부담.

## 5. 결론
설계 목표(실시간 0.5초 이하, 무중단 24h 녹화, 저부하 녹화)를 모두 충족.
세부 수치는 최종 보고서 "성능 검증" 표 및 `표1_성능검증` 도표와 일치.

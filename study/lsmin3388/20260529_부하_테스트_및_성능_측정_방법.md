# 부하 테스트 및 성능 측정 방법

## 학습 배경
통합 테스트 단계에서 실시간 스트리밍 지연과 다중 채널 안정성을 정량적으로
측정해야 했다. 영상 시스템 특성상 일반 웹 부하 도구만으로는 부족해 측정 방법을 정리.

## 핵심 개념
- **WebRTC 지연 측정**: 브라우저 DevTools의 WebRTC internals(`chrome://webrtc-internals`)에서
  jitter buffer, RTT, framesDecoded를 관찰하거나, 화면에 시계를 띄워 실물-화면 차이를 비교.
- **채널 부하**: 동시 채널 수를 늘리며 프레임 드랍/프리즈 관측. 네트워크 대역폭이 1차 병목.
- **리소스 측정**: `docker stats`로 컨테이너별 CPU/메모리. recorder는 codec copy라 저부하.
- **녹화 무결성**: `ffprobe`로 세그먼트 타임스탬프 연속성 확인.

## 프로젝트 적용
- 실시간 지연 목표(0.5초 이하)를 화면-실물 비교 + WebRTC stats 병행으로 검증.
- 2~4채널 동시 스트리밍에서 프레임 드랍 미관측 확인.
- codec copy 덕분에 녹화 CPU가 낮아 실시간+녹화 병행 시 여유 확인.

## 교훈
영상 시스템 성능은 단일 수치보다 "지연 / 부하 / 무결성" 세 축으로 나눠 봐야 한다.
대역폭 병목은 코드가 아니라 네트워크(PoE/업링크)에서 먼저 발생.

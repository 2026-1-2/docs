# Docker 배포 운영 트러블슈팅

## 학습 배경
Docker Compose로 다중 컨테이너(MediaMTX, recorder, mmp-server, client, nginx)를
배포하면서 겪은 문제와 해결 패턴을 정리.

## 핵심 개념 / 사례
- **컨테이너 간 통신**: 서비스명 기반 DNS로 통신. `localhost`가 아니라 서비스명 사용.
- **재시작 정책**: `restart: unless-stopped`로 호스트 재부팅/크래시 시 자동 복구.
- **헬스체크**: 컨테이너가 "기동"과 "정상 동작"은 다름 → healthcheck로 실제 준비 상태 확인.
- **볼륨**: 녹화본/설정은 볼륨으로 영속화. 컨테이너 재생성 시 데이터 유지.
- **포트/네트워크**: 외부 노출은 nginx만, 나머지는 내부 네트워크로 격리(보안).

## 자주 만난 문제
| 증상 | 원인 | 해결 |
|---|---|---|
| 컨테이너는 떴는데 연결 실패 | 기동≠준비 | healthcheck/대기 |
| 재부팅 후 일부 서비스 미기동 | restart 정책 누락 | unless-stopped |
| 설정 변경이 반영 안 됨 | 이미지 캐시/볼륨 | rebuild/볼륨 점검 |

## 프로젝트 적용
- 환경 의존성 제거 → 어느 호스트에서도 재현 가능한 배포(신뢰성).
- 운영 절차는 infra/DEPLOYMENT.md, 장애 대응은 infra/TROUBLESHOOTING.md로 문서화.

## 교훈
"내 PC에선 됐는데"를 없애는 게 컨테이너화의 핵심. 기동과 준비를 구분하는 healthcheck가
운영 안정성에 크게 기여.

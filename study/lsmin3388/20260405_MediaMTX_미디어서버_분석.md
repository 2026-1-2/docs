# MediaMTX 미디어 서버 분석

## 1. MediaMTX란?

MediaMTX(구 rtsp-simple-server)는 Go 언어로 작성된 오픈소스 미디어 서버이다.
RTSP, RTMP, HLS, WebRTC, SRT 등 다양한 프로토콜 간 변환을 지원하며,
설정 파일 하나로 멀티 프로토콜 스트리밍 서버를 구성할 수 있다.

---

## 2. 프로젝트에서의 역할

```
CCTV Camera ──RTSP──▶ MediaMTX ──WebRTC──▶ 브라우저 (실시간)
                         │
                         └──HLS──▶ 브라우저 (VOD/폴백)
```

MediaMTX는 프로토콜 변환 허브 역할을 한다.
카메라는 RTSP만 지원하지만, 브라우저는 RTSP를 직접 재생할 수 없기 때문에 중간 변환이 필수적이다.

---

## 3. 지원 프로토콜 비교

| 프로토콜 | 방향 | 지연 시간 | 브라우저 지원 | 용도 |
|----------|------|-----------|---------------|------|
| RTSP | 입력/출력 | ~1초 | 불가 | 카메라 연결 |
| RTMP | 입력/출력 | ~2초 | 불가 (Flash 종료) | 라이브 송출 |
| HLS | 출력 | 5~30초 | 완벽 지원 | VOD, 폴백 |
| WebRTC | 출력 | ~0.5초 | 완벽 지원 | 실시간 모니터링 |
| SRT | 입력/출력 | ~1초 | 불가 | 원격 전송 |

---

## 4. 핵심 설정 (mediamtx.yml)

### 4-1. 기본 설정

```yaml
api: yes
apiAddress: :9997

rtsp: yes
rtspAddress: :8554

hls: yes
hlsAddress: :8888

webrtc: yes
webrtcAddress: :8889
```

### 4-2. 카메라 경로 설정

```yaml
paths:
  cam1:
    source: rtsp://admin:password@192.168.0.101:554/Streaming/Channels/101
    rtspTransport: tcp
    sourceOnDemand: yes

  cam2:
    source: rtsp://admin:password@192.168.0.102:554/Streaming/Channels/101
    rtspTransport: tcp
    sourceOnDemand: yes
```

### 4-3. sourceOnDemand 옵션

| 값 | 동작 | 적합한 상황 |
|-----|------|-------------|
| `yes` | 클라이언트 접속 시에만 카메라 연결 | 대역폭 절약, 비상시 모니터링 |
| `no` | 서버 시작 시 항상 카메라 연결 | 상시 녹화, 이벤트 감지 |

## 5. REST API 활용

MediaMTX는 REST API를 통해 런타임에 스트림을 동적으로 관리할 수 있다.

### 5-1. 경로 목록 조회

```bash
GET http://localhost:9997/v3/paths/list
```

응답:
```json
{
  "items": [
    {
      "name": "cam1",
      "source": { "type": "rtspSource" },
      "ready": true,
      "readers": [{ "type": "webRTCSession" }]
    }
  ]
}
```

### 5-2. 경로 동적 추가

```bash
POST http://localhost:9997/v3/config/paths/add/cam3
Content-Type: application/json

{
  "source": "rtsp://admin:password@192.168.0.103:554/Streaming/Channels/101",
  "rtspTransport": "tcp"
}
```

### 5-3. 경로 삭제

```bash
DELETE http://localhost:9997/v3/config/paths/delete/cam3
```

프로젝트의 mmp-server에서 이 API를 활용하여 카메라 추가/삭제 시 MediaMTX에 자동으로 경로를 등록/제거한다.

## 6. Docker 환경에서의 포트 설정

```yaml
services:
  mediamtx:
    image: bluenviron/mediamtx:latest
    ports:
      - "8554:8554"       # RTSP
      - "8889:8889"       # WebRTC 시그널링 (TCP)
      - "8189:8189/udp"   # WebRTC 미디어 데이터 (UDP)
      - "8888:8888"       # HLS
      - "9997:9997"       # REST API
```

WebRTC의 UDP 포트(`8189`)는 반드시 호스트와 컨테이너의 포트 번호를 일치시켜야 한다.
포트 불일치 시 `deadline exceeded while waiting connection` 에러가 발생한다.

---

## 7. WebRTC 연결 실패 대응

VMware나 NAT 환경에서 WebRTC 연결이 실패하는 경우:

```yaml
# mediamtx.yml에 추가
webrtcAdditionalHosts: [192.168.0.200]
webrtcLocalUDPAddress: :8189
```

`webrtcAdditionalHosts`에 실제 접근 가능한 IP를 명시하면,
ICE candidate에 해당 IP가 포함되어 브라우저가 올바른 주소로 연결할 수 있다.

---

## 8. 성능 특성

- Go 언어의 고루틴 기반으로 수백 개의 동시 스트림 처리 가능
- 프로토콜 변환(RTSP→WebRTC)은 트랜스코딩이 아닌 리먹싱(Remuxing)이므로 CPU 부하가 매우 낮다
- H.265→H.264 변환이 필요한 경우에만 FFmpeg을 호출하여 트랜스코딩 수행

# MySQL 데이터베이스 설계

## 1. 개요

버티포트 CCTV 감시 시스템에서 관리해야 하는 데이터를 분석하고,
MySQL 데이터베이스의 테이블 구조와 관계를 설계한다.

---

## 2. 엔티티 분석

시스템에서 관리해야 하는 주요 엔티티:

| 엔티티 | 설명 |
|--------|------|
| User | 시스템 사용자 (관리자, 운영자) |
| Camera | CCTV 카메라 장치 정보 |
| StreamSession | 스트리밍 세션 (시작/종료 기록) |
| ActivityLog | 사용자 활동 로그 |
| InfraLog | 인프라 상태 로그 (CPU, 메모리 등) |

## 4. Prisma Schema 설계

```prisma
generator client {
  provider = "prisma-client-js"
}

datasource db {
  provider = "mysql"
  url      = env("DATABASE_URL")
}

model User {
  id        Int      @id @default(autoincrement())
  username  String   @unique
  email     String   @unique
  password  String
  role      Role     @default(OPERATOR)
  createdAt DateTime @default(now()) @map("created_at")
  updatedAt DateTime @updatedAt @map("updated_at")

  activityLogs ActivityLog[]

  @@map("users")
}

enum Role {
  ADMIN
  OPERATOR
}

model Camera {
  id        Int      @id @default(autoincrement())
  name      String
  ipAddress String   @map("ip_address")
  rtspPort  Int      @default(554) @map("rtsp_port")
  rtspPath  String   @map("rtsp_path")
  username  String
  password  String
  location  String?
  isActive  Boolean  @default(true) @map("is_active")
  createdAt DateTime @default(now()) @map("created_at")
  updatedAt DateTime @updatedAt @map("updated_at")

  streamSessions StreamSession[]

  @@map("cameras")
}

model StreamSession {
  id        Int       @id @default(autoincrement())
  cameraId  Int       @map("camera_id")
  protocol  String
  startedAt DateTime  @default(now()) @map("started_at")
  endedAt   DateTime? @map("ended_at")
  clientIp  String?   @map("client_ip")
  createdAt DateTime  @default(now()) @map("created_at")

  camera Camera @relation(fields: [cameraId], references: [id])

  @@map("stream_sessions")
}

model ActivityLog {
  id        Int      @id @default(autoincrement())
  userId    Int?     @map("user_id")
  action    String
  target    String?
  detail    String?  @db.Text
  ipAddress String?  @map("ip_address")
  createdAt DateTime @default(now()) @map("created_at")

  user User? @relation(fields: [userId], references: [id])

  @@map("activity_logs")
}

model InfraLog {
  id         Int      @id @default(autoincrement())
  cpuUsage   Float    @map("cpu_usage")
  memUsage   Float    @map("mem_usage")
  diskUsage  Float    @map("disk_usage")
  createdAt  DateTime @default(now()) @map("created_at")

  @@map("infra_logs")
}
```

## 5. 네이밍 컨벤션

| 구분 | Prisma (코드) | MySQL (DB) |
|------|---------------|------------|
| 모델명 | PascalCase (`StreamSession`) | snake_case (`stream_sessions`) |
| 필드명 | camelCase (`ipAddress`) | snake_case (`ip_address`) |
| 관계 | `camera Camera @relation(...)` | FK 컬럼 (`camera_id`) |

`@map()` 데코레이터로 코드의 camelCase를 DB의 snake_case로 매핑한다.
`@@map()` 데코레이터로 모델명을 테이블명으로 매핑한다.

## 6. 인덱스 전략

자주 조회되는 컬럼에 인덱스를 추가하여 쿼리 성능을 향상시킨다.

```prisma
model ActivityLog {
  // ...
  @@index([createdAt])          // 시간 범위 조회
  @@index([userId])             // 사용자별 조회
  @@index([action])             // 액션별 필터링
}

model StreamSession {
  // ...
  @@index([cameraId])           // 카메라별 세션 조회
  @@index([startedAt])          // 시간 범위 조회
}
```

## 7. Migration 관리

```bash
# 스키마 변경 후 마이그레이션 생성
npx prisma migrate dev --name add_infra_logs

# 운영 환경 마이그레이션 적용
npx prisma migrate deploy

# 현재 스키마 상태 확인
npx prisma db pull

# Prisma Client 재생성
npx prisma generate
```

마이그레이션 파일은 `prisma/migrations/` 디렉토리에 타임스탬프와 함께 저장되며, Git으로 버전 관리한다.

## 8. 데이터 보안 고려사항

- 카메라 비밀번호는 평문 저장하지 않고 암호화 처리 (AES-256)
- 사용자 비밀번호는 bcrypt 해시 저장
- `DATABASE_URL`에 비밀번호가 포함되므로 `.env`에서 관리하고 `.gitignore`에 추가
- ActivityLog를 통해 모든 중요 작업에 대한 감사 추적(Audit Trail) 유지

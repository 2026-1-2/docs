# 시스템 모니터링 및 로깅 전략

## 학습 배경
관제 시스템은 24시간 운영되므로, 장애를 사전 인지하고 사후 추적할 수 있는
모니터링/로깅 체계가 필요. 인프라 관점에서 정리.

## 핵심 개념
- **로그 레벨**: ERROR/WARN/INFO 구분, 운영에선 과도한 DEBUG 지양.
- **상태 가시성**: 컨테이너 상태, 카메라 연결, 녹화 프로세스 생존 여부.
- **시스템 로그 화면**: client의 SystemLogs 페이지에서 이벤트 조회 → 사용자 가시성.
- **이벤트 기록**: 카메라 등록/삭제, 연결 단절/복구, cleanup 동작 등 핵심 이벤트 기록.

## 프로젝트 적용
- 시스템 이벤트를 기록하고 관제 UI에서 조회 가능하게 구성.
- 녹화 프로세스/카메라 연결 상태를 주기적으로 점검해 이상 시 자동 재시작.
- 보안 관점에서 접근/제어 행위 로깅(부인 방지) 권고 → 보안 체크리스트와 연계.

## 교훈
"문제가 났는지 모르는 상태"가 가장 위험. 무중단 시스템일수록 상태를 드러내는
모니터링이 기능 개발만큼 중요하다.

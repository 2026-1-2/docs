# RTSP 프로토콜 이해와 영상 스트리밍 기초

## 1. RTSP(Real Time Streaming Protocol)란?

RTSP는 실시간 미디어 스트리밍을 제어하기 위한 애플리케이션 레벨 프로토콜이다.
RFC 2326에 정의되어 있으며, 주로 CCTV 카메라와 미디어 서버 간 영상 전송에 사용된다.

RTSP 자체는 미디어 데이터를 전송하지 않고, 스트리밍 세션의 설정/제어만 담당한다.
실제 미디어 데이터는 RTP(Real-time Transport Protocol)로 전송된다.

---

## 2. RTSP URL 구조

```
rtsp://[사용자]:[비밀번호]@[IP주소]:[포트]/[경로]
```

Hikvision 카메라 예시:
```
rtsp://admin:password@192.168.0.101:554/Streaming/Channels/101
```

- `/Streaming/Channels/101`: 채널 1, 메인 스트림
- `/Streaming/Channels/102`: 채널 1, 서브 스트림 (저해상도)

## 3. RTSP 동작 과정

```
Client                          Camera (RTSP Server)
  │                                │
  │──── OPTIONS ──────────────────▶│  지원 메서드 확인
  │◀─── 200 OK ───────────────────│
  │                                │
  │──── DESCRIBE ─────────────────▶│  미디어 정보 요청 (SDP)
  │◀─── 200 OK + SDP ────────────│
  │                                │
  │──── SETUP ────────────────────▶│  전송 채널 설정 (UDP/TCP)
  │◀─── 200 OK ───────────────────│
  │                                │
  │──── PLAY ─────────────────────▶│  스트리밍 시작
  │◀─── 200 OK ───────────────────│
  │◀════ RTP 데이터 ══════════════│  영상/음성 데이터 수신
  │                                │
  │──── TEARDOWN ─────────────────▶│  세션 종료
  │◀─── 200 OK ───────────────────│
```

## 4. 전송 모드: UDP vs TCP

### UDP 모드 (기본)

```
RTSP 제어: TCP 554
미디어 전송: UDP (RTP 포트 동적 할당)
```

- 장점: 낮은 지연 시간
- 단점: 패킷 유실 시 화면 깨짐, 방화벽 통과 어려움

### TCP Interleaved 모드

```
RTSP 제어 + 미디어 전송: TCP 554 (하나의 연결)
```

- 장점: 방화벽 통과 용이, 패킷 유실 없음
- 단점: TCP 오버헤드로 약간의 지연 증가

프로젝트에서는 안정성을 위해 TCP 모드를 사용한다:
```yaml
# mediamtx.yml
paths:
  cam1:
    source: rtsp://admin:password@192.168.0.101:554/Streaming/Channels/101
    rtspTransport: tcp
```

## 5. SDP(Session Description Protocol)

DESCRIBE 요청의 응답으로 받는 SDP에는 미디어 스트림 정보가 포함된다.

```
v=0
o=- 1234567890 1234567890 IN IP4 192.168.0.101
s=Media Presentation
t=0 0
m=video 0 RTP/AVP 96
a=rtpmap:96 H264/90000
a=control:trackID=1
```

주요 필드:
- `m=video`: 비디오 스트림
- `a=rtpmap:96 H264/90000`: H.264 코덱, 90kHz 클럭
- `a=control:trackID=1`: 트랙 식별자

---

## 6. 코덱 비교: H.264 vs H.265

| 항목 | H.264 (AVC) | H.265 (HEVC) |
|------|-------------|---------------|
| 압축 효율 | 기준 | H.264 대비 약 50% 향상 |
| 대역폭 | 높음 | 낮음 |
| CPU 부하 | 낮음 | 높음 |
| 브라우저 지원 | 모든 브라우저 | 제한적 (Safari 위주) |
| WebRTC 호환 | 완벽 지원 | 미지원 (트랜스코딩 필요) |

프로젝트에서는 WebRTC 호환성을 위해 카메라 코덱을 H.264로 설정해야 한다.

## 7. RTSP 테스트 방법

### VLC 플레이어로 확인

```
1. VLC 실행
2. 미디어 → 네트워크 스트림 열기
3. URL 입력: rtsp://admin:password@192.168.0.101:554/Streaming/Channels/101
4. 재생
```

### FFmpeg으로 확인

```bash
ffprobe -rtsp_transport tcp rtsp://admin:password@192.168.0.101:554/Streaming/Channels/101
```

출력에서 코덱, 해상도, 프레임레이트를 확인할 수 있다.

### FFmpeg으로 녹화 테스트

```bash
ffmpeg -rtsp_transport tcp \
  -i rtsp://admin:password@192.168.0.101:554/Streaming/Channels/101 \
  -c copy -t 10 test_output.mp4
```

`-c copy`: 트랜스코딩 없이 원본 코덱 그대로 저장 (CPU 부하 최소화)

---

## 8. 프로젝트에서의 RTSP 활용

1. **MediaMTX**: RTSP 입력을 받아 WebRTC/HLS로 프로토콜 변환
2. **video-recorder**: RTSP 입력을 FFmpeg으로 받아 MP4 세그먼트 녹화
3. **카메라 설정**: H.264 코덱, 메인 스트림(고해상도) + 서브 스트림(저해상도)

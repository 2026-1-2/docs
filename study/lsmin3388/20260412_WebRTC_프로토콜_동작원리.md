# WebRTC 프로토콜 동작 원리

## 1. WebRTC란?

WebRTC(Web Real-Time Communication)는 브라우저 간 플러그인 없이 실시간 음성, 영상, 데이터를 주고받을 수 있는 오픈 표준 기술이다. Google이 오픈소스로 공개했으며 W3C와 IETF에서 표준화되었다.

CCTV 모니터링 시스템에서는 카메라 영상을 브라우저에서 초저지연으로 시청하기 위해 사용한다.

---

## 2. WebRTC vs HLS vs RTSP

| 항목 | WebRTC | HLS | RTSP |
|------|--------|-----|------|
| 지연 시간 | 0.5초 이하 | 5~30초 | 1~2초 |
| 브라우저 지원 | 네이티브 지원 | 네이티브 지원 | 미지원 |
| 프로토콜 | UDP (SRTP) | HTTP (TCP) | TCP/UDP |
| 적합한 용도 | 실시간 모니터링 | VOD, 녹화 재생 | 카메라 직접 연결 |
| NAT 통과 | ICE/STUN/TURN | 문제 없음 | 어려움 |

## 3. WebRTC 연결 수립 과정

### 3-1. 시그널링 (Signaling)

WebRTC 자체에는 시그널링 표준이 없다. 별도의 시그널링 서버를 통해 SDP(Session Description Protocol)를 교환해야 한다.

```
Browser                    MediaMTX
  │                           │
  │── HTTP POST (SDP Offer)──▶│   WHEP 엔드포인트
  │◀── HTTP 201 (SDP Answer)──│
  │                           │
  │◀═══ SRTP (영상 데이터) ═══│   UDP 미디어 전송
```

프로젝트에서는 MediaMTX의 WHEP(WebRTC-HTTP Egress Protocol) 엔드포인트를 사용한다.

### 3-2. SDP (Session Description Protocol)

SDP는 미디어 세션의 메타데이터를 기술하는 텍스트 형식이다.

```
v=0
o=- 0 0 IN IP4 0.0.0.0
s=-
t=0 0
m=video 9 UDP/TLS/RTP/SAVPF 96
a=rtpmap:96 H264/90000
a=ice-ufrag:abcd
a=ice-pwd:efghijkl
a=candidate:1 1 udp 2130706431 192.168.0.200 8189 typ host
```

포함 정보: 코덱 종류, ICE 후보(candidate), 네트워크 주소

### 3-3. ICE (Interactive Connectivity Establishment)

ICE는 두 피어 간 최적의 네트워크 경로를 찾는 프레임워크이다.

```
ICE Candidate 유형:
  ├── host:   로컬 IP (192.168.x.x)
  ├── srflx:  STUN 서버를 통해 알아낸 공인 IP
  └── relay:  TURN 서버를 통한 중계 (최후 수단)
```

### 3-4. STUN과 TURN

```
                    ┌──────────┐
                    │  STUN    │
                    │  Server  │
                    └────┬─────┘
                         │ "너의 공인 IP는 1.2.3.4야"
                         │
┌─────────┐         ┌────┴────┐
│ Browser │◀═══════▶│ MediaMTX│
└─────────┘  UDP    └─────────┘

STUN: 자신의 공인 IP를 알아내는 용도 (가벼움)
TURN: 직접 통신 불가 시 미디어 데이터를 중계 (비용 높음)
```

같은 로컬 네트워크에서는 STUN/TURN 없이 host candidate만으로 연결 가능하다.

## 4. WHEP (WebRTC-HTTP Egress Protocol)

WHEP는 WebRTC 스트림을 수신하기 위한 HTTP 기반 표준 프로토콜이다.
MediaMTX에서 WHEP 엔드포인트를 제공한다.

```
브라우저 → POST http://mediamtx:8889/cam1
           Body: SDP Offer
           
MediaMTX → 201 Created
           Body: SDP Answer
           Location: /cam1/session-id
```

프론트엔드에서의 사용:

```javascript
const pc = new RTCPeerConnection();

pc.ontrack = (event) => {
  videoElement.srcObject = event.streams[0];
};

pc.addTransceiver('video', { direction: 'recvonly' });

const offer = await pc.createOffer();
await pc.setLocalDescription(offer);

const response = await fetch('http://mediamtx:8889/cam1', {
  method: 'POST',
  headers: { 'Content-Type': 'application/sdp' },
  body: pc.localDescription.sdp,
});

const answer = await response.text();
await pc.setRemoteDescription({ type: 'answer', sdp: answer });
```

## 5. 프로젝트에서의 WebRTC 구현

### 5-1. 아키텍처

```
Camera ──RTSP──▶ MediaMTX ──WHEP──▶ React (WebRtcPlayer 컴포넌트)
```

### 5-2. 지연 시간 최적화

- `rtspTransport: tcp`로 패킷 유실 방지
- MediaMTX의 `webrtcLocalUDPAddress`로 UDP Mux 활성화
- 브라우저에서 `RTCPeerConnection`의 ICE gathering 타임아웃 조정

### 5-3. 폴백 전략

WebRTC 연결 실패 시 HLS로 자동 전환:

```
WebRTC 시도 → 실패 → HLS 폴백 (http://mediamtx:8888/cam1)
```

HLS는 지연이 크지만 HTTP 기반이라 방화벽/NAT 환경에서 안정적으로 동작한다.

## 6. 트러블슈팅

| 증상 | 원인 | 해결 |
|------|------|------|
| `deadline exceeded` | UDP 포트 차단 또는 포트 불일치 | Docker 포트 매핑 확인 (`8189:8189/udp`) |
| 검은 화면 | H.265 코덱 사용 | 카메라 코덱을 H.264로 변경 |
| 연결 후 끊김 | ICE candidate에 잘못된 IP | `webrtcAdditionalHosts` 설정 |
| 404 Not Found | 경로명 불일치 | URL 대소문자, 슬래시 확인 |

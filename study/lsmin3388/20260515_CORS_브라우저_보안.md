# CORS 정책과 브라우저 보안

> **작성일**: 2026-05-15
> **작성자**: lsmin3388
> **프로젝트**: 버티포트 CCTV 감시 시스템

## 1. 개요

버티포트 CCTV 감시 시스템은 React 프론트엔드(포트 5173)와 NestJS 백엔드(포트 3000)가 분리된 구조다. 서로 다른 출처(Origin) 간 API 호출 시 브라우저의 **CORS(Cross-Origin Resource Sharing)** 정책을 정확히 이해하고 설정해야 한다.

## 2. Same-Origin Policy (동일 출처 정책)

브라우저는 보안을 위해 **동일 출처 정책**을 적용한다. 출처(Origin)는 프로토콜 + 호스트 + 포트의 조합이다.

| 요청 출처 | 대상 출처 | 동일 출처 | 이유 |
|-----------|-----------|----------|------|
| `http://localhost:5173` | `http://localhost:3000` | X | 포트 상이 |
| `https://vertiport.knu.ac.kr` | `https://vertiport.knu.ac.kr/api` | O | 경로만 다름 |
| `http://localhost:5173` | `https://localhost:5173` | X | 프로토콜 상이 |

## 3. CORS 동작 원리

### 3.1 Simple Request vs Preflight Request

Simple Request 조건: 메서드가 `GET/HEAD/POST`, Content-Type이 `text/plain` 등 단순 타입. 우리 프로젝트는 `Content-Type: application/json`을 사용하므로 대부분 **Preflight(OPTIONS)** 가 발생한다.

```
OPTIONS /api/events HTTP/1.1
Origin: http://localhost:5173
Access-Control-Request-Method: POST
Access-Control-Request-Headers: Content-Type, Authorization
```

### 3.2 CORS 주요 헤더

| 헤더 | 설명 |
|------|------|
| `Access-Control-Allow-Origin` | 허용할 출처 (`*` 또는 특정 Origin) |
| `Access-Control-Allow-Methods` | 허용할 HTTP 메서드 목록 |
| `Access-Control-Allow-Headers` | 허용할 요청 헤더 목록 |
| `Access-Control-Allow-Credentials` | 쿠키/인증 정보 포함 허용 여부 |
| `Access-Control-Max-Age` | Preflight 캐싱 시간 (초) |

> **주의**: `Allow-Origin: *`와 `Allow-Credentials: true`는 동시에 사용할 수 없다.

## 4. NestJS에서의 CORS 설정

### 4.1 기본 설정 (app.enableCors)

```typescript
// main.ts
async function bootstrap() {
  const app = await NestFactory.create(AppModule);
  app.enableCors({
    origin: ['http://localhost:5173', 'https://vertiport.knu.ac.kr'],
    methods: ['GET', 'POST', 'PUT', 'DELETE', 'PATCH'],
    allowedHeaders: ['Content-Type', 'Authorization'],
    credentials: true,
    maxAge: 86400,
  });
  await app.listen(3000);
}
```

### 4.2 환경별 동적 Origin 설정

```typescript
app.enableCors({
  origin: (origin, callback) => {
    const allowedOrigins = process.env.CORS_ORIGINS?.split(',') || [];
    if (!origin || allowedOrigins.includes(origin)) {
      callback(null, true);
    } else {
      callback(new Error(`CORS 차단: ${origin}`));
    }
  },
  credentials: true,
});
```

```env
# .env.development
CORS_ORIGINS=http://localhost:5173,http://localhost:3000
# .env.production
CORS_ORIGINS=https://vertiport.knu.ac.kr
```

## 5. 프록시를 통한 CORS 우회

### 5.1 Vite 개발 서버 프록시

프록시를 사용하면 브라우저 입장에서 동일 출처 요청이 되어 CORS 문제가 발생하지 않는다.

```typescript
// vite.config.ts
export default defineConfig({
  server: {
    proxy: {
      '/api': { target: 'http://localhost:3000', changeOrigin: true },
      '/stream': { target: 'http://localhost:8889', changeOrigin: true, ws: true },
    },
  },
});
```

### 5.2 Nginx 리버스 프록시 (운영 환경)

```nginx
server {
    listen 443 ssl;
    server_name vertiport.knu.ac.kr;

    location / {
        root /usr/share/nginx/html;
        try_files $uri $uri/ /index.html;
    }
    location /api/ {
        proxy_pass http://nestjs-app:3000/;
        proxy_set_header Host $host;
        proxy_set_header X-Forwarded-Proto $scheme;
    }
    location /stream/ {
        proxy_pass http://mediamtx:8889/;
        proxy_http_version 1.1;
        proxy_set_header Upgrade $http_upgrade;
        proxy_set_header Connection "upgrade";
    }
}
```

## 6. 개발 환경 vs 운영 환경 CORS 전략

| 항목 | 개발 환경 | 운영 환경 |
|------|-----------|-----------|
| CORS 처리 | Vite proxy로 우회 | Nginx 리버스 프록시로 통합 |
| Origin 설정 | `localhost:5173` 허용 | 도메인 특정 Origin만 허용 |
| Credentials | 개발 편의상 허용 | JWT Bearer 토큰 사용 |
| HTTPS | 불필요 | 필수 (Let's Encrypt) |

## 7. XSS (Cross-Site Scripting) 방어

공격자가 악성 스크립트를 삽입하여 사용자 정보를 탈취하는 공격이다.

```typescript
// React는 JSX 내 문자열을 자동 이스케이프 (안전)
const CameraName = ({ name }: { name: string }) => <span>{name}</span>;

// dangerouslySetInnerHTML 사용 시 반드시 새니타이징
import DOMPurify from 'dompurify';
const EventDetail = ({ html }: { html: string }) => (
  <div dangerouslySetInnerHTML={{ __html: DOMPurify.sanitize(html) }} />
);
```

```typescript
// NestJS Helmet 미들웨어로 CSP 헤더 추가
import helmet from 'helmet';
app.use(helmet({
  contentSecurityPolicy: {
    directives: {
      defaultSrc: ["'self'"],
      scriptSrc: ["'self'"],
      connectSrc: ["'self'", "wss://vertiport.knu.ac.kr"],
    },
  },
}));
```

## 8. CSRF (Cross-Site Request Forgery) 방어

인증된 사용자의 브라우저를 이용해 의도하지 않은 요청을 보내는 공격이다.

| 방어 기법 | 설명 | 적용 여부 |
|-----------|------|-----------|
| SameSite 쿠키 | 크로스 사이트 쿠키 전송 차단 | O |
| CSRF 토큰 | 서버 발급 토큰을 요청에 포함 | 선택 |
| JWT Bearer 토큰 | Authorization 헤더로 전송 | O (주 방식) |

우리 프로젝트는 JWT를 Authorization 헤더로 전송하므로 쿠키 기반 CSRF에 안전하다.

```typescript
const fetchCameras = async () => {
  const token = localStorage.getItem('accessToken');
  const res = await fetch('/api/cameras', {
    headers: { 'Authorization': `Bearer ${token}` },
  });
  return res.json();
};
```

## 9. CORS 디버깅 체크리스트

1. 브라우저 콘솔에서 차단된 Origin 확인
2. Network 탭에서 OPTIONS Preflight 요청 확인
3. 서버 응답 헤더에 `Access-Control-Allow-Origin` 포함 확인
4. credentials 사용 시 `*` 대신 특정 Origin 설정 확인

```bash
# curl로 Preflight 시뮬레이션
curl -X OPTIONS http://localhost:3000/api/cameras \
  -H "Origin: http://localhost:5173" \
  -H "Access-Control-Request-Method: GET" \
  -v 2>&1 | grep -i "access-control"
```

## 10. 요약

- **Same-Origin Policy**는 브라우저의 기본 보안 정책으로, 다른 출처 간 리소스 접근을 제한한다.
- **CORS**는 서버가 응답 헤더를 통해 특정 출처의 접근을 명시적으로 허용하는 메커니즘이다.
- 개발: **Vite proxy**, 운영: **Nginx 리버스 프록시**로 CORS를 처리한다.
- **XSS**는 React 자동 이스케이프 + Helmet CSP로, **CSRF**는 JWT Bearer 토큰으로 방어한다.

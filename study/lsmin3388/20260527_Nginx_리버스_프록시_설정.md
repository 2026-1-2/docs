# Nginx 리버스 프록시 설정

## 1. 리버스 프록시란?

리버스 프록시는 클라이언트와 백엔드 서버 사이에 위치하여 요청을 적절한 서버로 전달하는 중간 서버이다.

```
Client ──▶ Nginx (80/443) ──▶ mmp-server (3000)
                            ──▶ MediaMTX (8889)
                            ──▶ Client (5173)
```

---

## 2. 도입 이유

| 문제 | 해결 |
|------|------|
| 여러 서비스가 각각 다른 포트 사용 | 단일 도메인에서 경로 기반 라우팅 |
| CORS 문제 | 같은 Origin으로 통합 |
| HTTPS 적용 | Nginx에서 SSL 종료(Termination) |
| 로드 밸런싱 | 트래픽 분산 (향후 확장) |

---

## 3. 기본 설정

### 3-1. 경로 기반 라우팅

```nginx
server {
    listen 80;
    server_name mmp.example.com;

    # 프론트엔드 (React)
    location / {
        proxy_pass http://localhost:5173;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
    }

    # 백엔드 API
    location /api/ {
        proxy_pass http://localhost:3000/;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
    }

    # WebRTC 시그널링
    location /webrtc/ {
        proxy_pass http://localhost:8889/;
        proxy_set_header Host $host;
        proxy_http_version 1.1;
    }

    # SSE (Server-Sent Events)
    location /events/ {
        proxy_pass http://localhost:3000/events/;
        proxy_set_header Connection '';
        proxy_http_version 1.1;
        chunked_transfer_encoding off;
        proxy_buffering off;
        proxy_cache off;
    }
}
```

### 3-2. SSE 프록시 주의사항

SSE는 장시간 열려 있는 HTTP 연결이므로 버퍼링을 반드시 비활성화해야 한다.

```nginx
proxy_buffering off;        # 응답 버퍼링 비활성화
proxy_cache off;            # 캐싱 비활성화
proxy_read_timeout 3600s;   # 타임아웃 늘림 (기본 60초)
```

이 설정이 없으면 Nginx가 SSE 이벤트를 버퍼에 쌓아두다가 한꺼번에 전달하여 실시간성이 깨진다.

## 4. WebSocket 프록시

WebSocket 업그레이드 요청을 처리하기 위한 설정:

```nginx
location /ws/ {
    proxy_pass http://localhost:3000;
    proxy_http_version 1.1;
    proxy_set_header Upgrade $http_upgrade;
    proxy_set_header Connection "upgrade";
    proxy_set_header Host $host;
}
```

`Upgrade`와 `Connection` 헤더를 전달해야 WebSocket 핸드셰이크가 성공한다.

## 5. HTTPS 설정 (Let's Encrypt)

### 5-1. 인증서 발급

```bash
sudo apt install certbot python3-certbot-nginx
sudo certbot --nginx -d mmp.example.com
```

### 5-2. 자동 갱신

```bash
sudo certbot renew --dry-run
```

Certbot이 자동으로 cron job을 등록하여 인증서를 갱신한다.

### 5-3. HTTPS 설정 (자동 생성)

```nginx
server {
    listen 443 ssl;
    server_name mmp.example.com;

    ssl_certificate /etc/letsencrypt/live/mmp.example.com/fullchain.pem;
    ssl_certificate_key /etc/letsencrypt/live/mmp.example.com/privkey.pem;

    # ... location 블록들
}

server {
    listen 80;
    server_name mmp.example.com;
    return 301 https://$server_name$request_uri;  # HTTP → HTTPS 리다이렉트
}
```

## 6. 성능 최적화

### 6-1. Gzip 압축

```nginx
gzip on;
gzip_types text/plain text/css application/json application/javascript;
gzip_min_length 1000;
```

### 6-2. 정적 파일 캐싱

```nginx
location /assets/ {
    proxy_pass http://localhost:5173/assets/;
    expires 30d;
    add_header Cache-Control "public, immutable";
}
```

### 6-3. 연결 제한

```nginx
# 동시 연결 수 제한
limit_conn_zone $binary_remote_addr zone=conn_limit:10m;
limit_conn conn_limit 50;

# 요청 속도 제한
limit_req_zone $binary_remote_addr zone=req_limit:10m rate=10r/s;
limit_req zone=req_limit burst=20 nodelay;
```

## 7. Docker Compose 통합

```yaml
services:
  nginx:
    image: nginx:alpine
    ports:
      - "80:80"
      - "443:443"
    volumes:
      - ./nginx/nginx.conf:/etc/nginx/conf.d/default.conf
      - ./certbot/conf:/etc/letsencrypt
    depends_on:
      - mmp-server
      - client
```

## 8. 프로젝트 적용 시 고려사항

- 개발 환경에서는 Vite의 proxy 설정으로 CORS를 우회하고, 운영 환경에서만 Nginx를 사용
- MediaMTX의 WebRTC 시그널링은 HTTP POST 요청이므로 일반 프록시로 전달 가능
- WebRTC의 UDP 미디어 데이터는 Nginx를 거치지 않고 직접 통신 (Nginx는 TCP 전용)
- SSE 연결의 타임아웃 설정을 충분히 늘려야 장시간 모니터링이 가능

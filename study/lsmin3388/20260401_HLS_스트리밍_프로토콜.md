# HLS(HTTP Live Streaming) 프로토콜 이해

## 학습 일자
2026.04.01

## 개요
HLS는 Apple이 개발한 적응형 비트레이트 스트리밍 프로토콜이다. 버티포트 시스템에서는 실시간 모니터링에 WebRTC를, VOD 재생과 WebRTC 폴백에 HLS를 활용한다. 본 문서에서는 HLS 동작 원리, MediaMTX 설정, 브라우저 구현, WebRTC 대비 장단점을 다룬다.

## 1. HLS 동작 원리

```
Hikvision ──RTSP──► MediaMTX ──HLS──► 브라우저(hls.js)
                  (index.m3u8 + seg_N.ts 생성)
```

### m3u8 매니페스트 - 라이브 vs VOD

```m3u8
# 라이브 (EXT-X-ENDLIST 없음 → 주기적 갱신)
#EXTM3U
#EXT-X-TARGETDURATION:6
#EXT-X-MEDIA-SEQUENCE:142
#EXTINF:6.006,
segment_142.ts
#EXTINF:6.006,
segment_143.ts
```

```m3u8
# VOD (EXT-X-ENDLIST로 종료 표시)
#EXTM3U
#EXT-X-PLAYLIST-TYPE:VOD
#EXTINF:6.006,
segment_0.ts
#EXT-X-ENDLIST
```

### 주요 태그

| 태그 | 설명 |
|------|------|
| `#EXT-X-TARGETDURATION` | 최대 세그먼트 길이(초) |
| `#EXT-X-MEDIA-SEQUENCE` | 첫 세그먼트 시퀀스 번호 |
| `#EXTINF` | 세그먼트 재생 시간 |
| `#EXT-X-ENDLIST` | VOD 종료 표시 |
| `#EXT-X-STREAM-INF` | ABR 스트림 정보 (해상도/비트레이트) |

## 2. HLS vs DASH 비교

| 항목 | HLS | DASH |
|------|-----|------|
| 개발사 | Apple | MPEG (국제 표준) |
| 세그먼트 형식 | .ts, .fmp4 | .m4s (fMP4) |
| 매니페스트 | .m3u8 (텍스트) | .mpd (XML) |
| 브라우저 지원 | Safari 네이티브 + hls.js | dash.js 필요 |
| 지연 시간 | 15~30초, LL-HLS 2~5초 | 3~5초 |
| iOS 지원 | 네이티브 | 제한적 |

**HLS 선택 이유**: MediaMTX 기본 지원, iOS Safari 호환, Nginx 정적 서빙 가능

## 3. Low-Latency HLS (LL-HLS)

세그먼트를 0.5~1초 파트(Part)로 분할하고, Blocking Reload로 매니페스트를 갱신하여 지연을 2~5초로 단축한다.

| 기능 | 기본 HLS | LL-HLS |
|------|----------|--------|
| 파트(Part) | 없음 | 0.5~1초 단위 |
| 매니페스트 갱신 | 폴링 | Blocking Reload |
| 전형적 지연 | 15~30초 | 2~5초 |

## 4. MediaMTX HLS 설정

```yaml
# mediamtx.yml 핵심 설정
hlsAddress: :8888
hlsVariant: lowLatency    # mpegts | fmp4 | lowLatency
hlsSegmentCount: 7
hlsSegmentDuration: 1s
hlsPartDuration: 200ms
hlsAllowOrigin: '*'

paths:
  cam1:
    source: rtsp://admin:password@192.168.1.64:554/Streaming/Channels/101
    sourceOnDemand: yes
```

| Variant | 지연 | 호환성 |
|---------|------|--------|
| `mpegts` | 15~30s | 최고 |
| `fmp4` | 5~10s | 높음 |
| `lowLatency` | 2~5s | 보통 |

## 5. 브라우저에서 hls.js 사용법

```bash
npm install hls.js
```

```tsx
// src/components/HlsPlayer.tsx
import { useEffect, useRef, useState } from 'react';
import Hls from 'hls.js';

const HlsPlayer = ({ src, autoPlay = true, muted = true }: {
  src: string; autoPlay?: boolean; muted?: boolean;
}) => {
  const videoRef = useRef<HTMLVideoElement>(null);
  const [error, setError] = useState<string | null>(null);

  useEffect(() => {
    const video = videoRef.current;
    if (!video) return;

    // Safari 네이티브 HLS
    if (video.canPlayType('application/vnd.apple.mpegurl')) {
      video.src = src;
      return;
    }
    if (!Hls.isSupported()) { setError('HLS 미지원 브라우저'); return; }

    const hls = new Hls({ lowLatencyMode: true, maxBufferLength: 10 });
    hls.loadSource(src);
    hls.attachMedia(video);
    hls.on(Hls.Events.MANIFEST_PARSED, () => autoPlay && video.play().catch(() => {}));
    hls.on(Hls.Events.ERROR, (_, data) => {
      if (!data.fatal) return;
      if (data.type === Hls.ErrorTypes.NETWORK_ERROR) hls.startLoad();
      else if (data.type === Hls.ErrorTypes.MEDIA_ERROR) hls.recoverMediaError();
      else { setError('재생 불가'); hls.destroy(); }
    });
    return () => hls.destroy();
  }, [src, autoPlay]);

  return (
    <div style={{ position: 'relative' }}>
      {error && <div className="error-overlay">{error}</div>}
      <video ref={videoRef} muted={muted} autoPlay={autoPlay} playsInline
        style={{ width: '100%', objectFit: 'cover' }} />
    </div>
  );
};
export default HlsPlayer;
```

## 6. VOD 재생에서의 HLS 활용

### FFmpeg으로 녹화 파일 변환

```bash
ffmpeg -i recording_20260401.mp4 \
  -codec: copy \
  -hls_time 6 \
  -hls_list_size 0 \
  -hls_segment_filename "segment_%04d.ts" \
  -f hls output.m3u8
```

### NestJS VOD API

```typescript
// src/vod/vod.controller.ts
@Controller('vod')
export class VodController {
  @Get(':id/index.m3u8')
  async getPlaylist(@Param('id') id: string, @Res() res: Response) {
    res.setHeader('Content-Type', 'application/vnd.apple.mpegurl');
    res.send(await this.vodService.getPlaylist(id));
  }

  @Get(':id/:segment')
  async getSegment(@Param('id') id: string, @Param('segment') seg: string, @Res() res: Response) {
    res.setHeader('Content-Type', 'video/mp2t');
    res.sendFile(await this.vodService.getSegmentPath(id, seg));
  }
}
```

## 7. WebRTC 대비 장단점

| 항목 | HLS | WebRTC |
|------|-----|--------|
| 지연 시간 | 2~30초 | 0.5~1초 |
| 프로토콜 | HTTP (TCP) | UDP/TCP |
| 확장성 | CDN 활용 (높음) | SFU 필요 (중간) |
| 방화벽 통과 | 쉬움 (80/443) | STUN/TURN 필요 |
| 서버 부하 | 낮음 (정적 파일) | 높음 (실시간 릴레이) |
| ABR | 내장 지원 | Simulcast 필요 |
| 양방향 통신 | 불가 | 가능 |

### 프로젝트 내 사용 전략

| 용도 | 프로토콜 | 이유 |
|------|----------|------|
| 실시간 모니터링 | WebRTC (WHEP) | 초저지연, PTZ 제어 즉각 반응 |
| VOD 재생 | HLS | FFmpeg 변환 후 Nginx 서빙, seek 가능 |
| 폴백 | LL-HLS | WebRTC 실패 시 자동 전환 |

WebRTC 3회 재시도 실패 시 HLS로 자동 폴백하는 `useStreamPlayer` 훅을 구현하여 안정성을 확보한다.

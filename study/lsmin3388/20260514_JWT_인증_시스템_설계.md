# JWT 인증/인가 시스템 설계

## 1. JWT(JSON Web Token)란?

JWT는 두 당사자 간 정보를 안전하게 전달하기 위한 JSON 기반 토큰 표준(RFC 7519)이다.
서버가 세션을 저장하지 않는 Stateless 인증 방식으로, 분산 환경에 적합하다.

---

## 2. JWT 구조

```
Header.Payload.Signature

eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9.
eyJzdWIiOjEsInVzZXJuYW1lIjoiYWRtaW4iLCJyb2xlIjoiQURNSU4iLCJpYXQiOjE3MTY...}.
SflKxwRJSMeKKF2QT4fwpMeJf36POk6yJV_adQssw5c
```

### Header

```json
{
  "alg": "HS256",
  "typ": "JWT"
}
```

### Payload

```json
{
  "sub": 1,
  "username": "admin",
  "role": "ADMIN",
  "iat": 1716000000,
  "exp": 1716086400
}
```

- `sub`: 사용자 ID
- `role`: 사용자 역할 (ADMIN / OPERATOR)
- `iat`: 발급 시간
- `exp`: 만료 시간

### Signature

```
HMACSHA256(
  base64UrlEncode(header) + "." + base64UrlEncode(payload),
  secret
)
```

## 3. 인증 흐름

```
Client                              Server
  │                                    │
  │── POST /auth/login ───────────────▶│
  │   { username, password }           │
  │                                    │  비밀번호 검증 (bcrypt.compare)
  │◀── 200 { access_token } ──────────│  JWT 토큰 발급
  │                                    │
  │── GET /cameras ───────────────────▶│
  │   Authorization: Bearer <token>    │
  │                                    │  JwtAuthGuard가 토큰 검증
  │◀── 200 [카메라 목록] ─────────────│
```

## 4. NestJS 구현

### 4-1. AuthService

```typescript
@Injectable()
export class AuthService {
  constructor(
    private readonly prisma: PrismaService,
    private readonly jwtService: JwtService,
  ) {}

  async login(username: string, password: string) {
    const user = await this.prisma.user.findUnique({ where: { username } });
    if (!user) throw new UnauthorizedException('사용자를 찾을 수 없습니다');

    const isValid = await bcrypt.compare(password, user.password);
    if (!isValid) throw new UnauthorizedException('비밀번호가 일치하지 않습니다');

    const payload = { sub: user.id, username: user.username, role: user.role };
    return { access_token: this.jwtService.sign(payload) };
  }

  async register(username: string, email: string, password: string) {
    const hashedPassword = await bcrypt.hash(password, 10);
    return this.prisma.user.create({
      data: { username, email, password: hashedPassword },
    });
  }
}
```

### 4-2. JwtStrategy (Passport)

```typescript
@Injectable()
export class JwtStrategy extends PassportStrategy(Strategy) {
  constructor(configService: ConfigService) {
    super({
      jwtFromRequest: ExtractJwt.fromAuthHeaderAsBearerToken(),
      ignoreExpiration: false,
      secretOrKey: configService.get<string>('JWT_SECRET'),
    });
  }

  validate(payload: any) {
    return { id: payload.sub, username: payload.username, role: payload.role };
  }
}
```

### 4-3. JwtAuthGuard (글로벌)

```typescript
@Injectable()
export class JwtAuthGuard extends AuthGuard('jwt') {
  constructor(private reflector: Reflector) {
    super();
  }

  canActivate(context: ExecutionContext) {
    const isPublic = this.reflector.getAllAndOverride<boolean>(IS_PUBLIC_KEY, [
      context.getHandler(),
      context.getClass(),
    ]);
    if (isPublic) return true;
    return super.canActivate(context);
  }
}
```

`@Public()` 데코레이터가 붙은 엔드포인트는 인증 없이 접근 가능하다.

### 4-4. RolesGuard

```typescript
@Injectable()
export class RolesGuard implements CanActivate {
  constructor(private reflector: Reflector) {}

  canActivate(context: ExecutionContext): boolean {
    const requiredRoles = this.reflector.getAllAndOverride<Role[]>(ROLES_KEY, [
      context.getHandler(),
      context.getClass(),
    ]);
    if (!requiredRoles) return true;

    const { user } = context.switchToHttp().getRequest();
    return requiredRoles.includes(user.role);
  }
}
```

## 5. 역할 기반 접근 제어 (RBAC)

| 역할 | 권한 |
|------|------|
| ADMIN | 모든 기능 접근 (사용자 관리, 카메라 추가/삭제, 설정 변경) |
| OPERATOR | 모니터링, 녹화 재생, PTZ 제어 |

```typescript
@Roles(Role.ADMIN)
@Delete(':id')
remove(@Param('id', ParseIntPipe) id: number) {
  return this.camerasService.remove(id);
}
```

## 6. 보안 고려사항

| 항목 | 대응 |
|------|------|
| 토큰 탈취 | 만료 시간을 짧게 설정 (24h), Refresh Token 도입 검토 |
| 비밀번호 저장 | bcrypt 해시 (salt rounds: 10) |
| JWT Secret | 환경 변수로 관리, 충분한 길이 (256bit 이상) |
| CORS | 허용 Origin을 명시적으로 지정 |
| Rate Limiting | 로그인 시도 횟수 제한 (brute force 방지) |

## 7. 토큰 만료 및 갱신 전략

현재 구현: Access Token만 사용 (24시간 만료)

향후 개선 방안:
```
Access Token:  15분 만료 (API 요청용)
Refresh Token: 7일 만료 (Access Token 갱신용, httpOnly Cookie 저장)
```

```
토큰 만료 시:
Client ── POST /auth/refresh ──▶ Server
          Cookie: refresh_token
          
Server ── 200 { access_token } ──▶ Client
          새 Access Token 발급
```

# 버티포트 CCTV 감시 시스템 아키텍처 설계

## 1. 개요

버티포트(Vertiport) 환경에서 CCTV 카메라를 통한 실시간 영상 모니터링, 녹화, 이벤트 감지를 수행하는 통합 감시 시스템의 전체 아키텍처를 설계한다.

---

## 2. 시스템 구성도

## 3. 계층별 역할

### 3-1. 프레젠테이션 계층 (Client)

| 기능 | 설명 |
|------|------|
| 실시간 모니터링 | WebRTC 기반 저지연 영상 스트리밍 |
| 카메라 월 | 다중 카메라 동시 표시 (Dockview 레이아웃) |
| PTZ 제어 | Pan/Tilt/Zoom 원격 카메라 조작 |
| VOD 재생 | 녹화 영상 HLS 기반 재생 |
| 이벤트 알림 | SSE 기반 실시간 이벤트 수신 |

### 3-2. 비즈니스 로직 계층 (mmp-server)

- **인증/인가**: JWT 기반 사용자 인증, Role 기반 접근 제어
- **카메라 관리**: CRUD, ONVIF 프로토콜을 통한 카메라 제어
- **스트림 관리**: MediaMTX REST API를 통한 스트림 라이프사이클 관리
- **로그 관리**: 활동 로그, 인프라 로그 기록 및 조회
- **시스템 모니터링**: CPU, 메모리, 디스크 사용량 조회

### 3-3. 미디어 계층 (MediaMTX + video-recorder)

- **MediaMTX**: RTSP 수신 → WebRTC/HLS 변환 및 배포
- **video-recorder**: RTSP 스트림을 받아 MP4 파일로 세그먼트 녹화

### 3-4. 데이터 계층 (MySQL)

- 카메라 정보, 사용자 정보, 스트림 세션, 활동/인프라 로그 저장
- Prisma ORM으로 타입 안전한 쿼리 수행

---

## 4. 통신 프로토콜

```
Client ↔ mmp-server: HTTP REST API, SSE (Server-Sent Events)
Client ↔ MediaMTX:   WebRTC (WHEP), HLS
mmp-server ↔ MySQL:  TCP (Prisma Client)
mmp-server ↔ MediaMTX: HTTP REST API (port 9997)
MediaMTX ↔ Camera:   RTSP over TCP
video-recorder ↔ Camera: RTSP over TCP (FFmpeg)
```

---

## 5. 데이터 흐름

### 5-1. 실시간 영상 스트리밍

```
Camera --RTSP--> MediaMTX --WebRTC--> Browser
                          --HLS-----> Browser (fallback)
```

### 5-2. 녹화 영상 재생

```
Camera --RTSP--> video-recorder --MP4--> 로컬 스토리지
                                          │
mmp-server (VOD API) ◀─── 파일 목록 조회 ──┘
    │
    ▼
MediaMTX --HLS--> Browser (VOD 재생)
```

### 5-3. 이벤트 감지 및 알림

```
Camera --alertStream--> mmp-server --SSE--> Browser (실시간 알림)
                            │
                            └──── Gmail 알림 발송
```

## 6. 기술 스택 선정 이유

| 기술 | 선정 이유 |
|------|-----------|
| React + TypeScript | 타입 안전성, 컴포넌트 기반 UI 구성 |
| NestJS | 모듈 기반 아키텍처, DI 패턴, TypeScript 네이티브 지원 |
| Prisma | 타입 안전 ORM, 직관적 migration 관리 |
| MySQL | 관계형 데이터 모델에 적합, 팀 내 경험 보유 |
| MediaMTX | Go 기반 고성능 미디어 서버, 멀티 프로토콜 지원 |
| Docker Compose | 멀티 컨테이너 환경 오케스트레이션 |

---

## 7. 확장성 고려사항

- 카메라 대수 증가 시 MediaMTX 인스턴스 수평 확장 가능
- 녹화 스토리지는 NAS 또는 오브젝트 스토리지로 확장 가능
- 이벤트 처리량 증가 시 메시지 큐(Redis Pub/Sub) 도입 검토
- 모니터링 대시보드는 Dockview 기반 커스터마이즈 가능한 레이아웃

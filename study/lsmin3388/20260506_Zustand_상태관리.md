# Zustand 상태관리 라이브러리 분석

## 1. 개요

버티포트 CCTV 감시 시스템의 React 프론트엔드는 카메라 목록, 레이아웃 설정, 날씨 정보, 사용자 인증 상태 등
다양한 전역 상태를 관리해야 한다. 본 문서에서는 경량 상태관리 라이브러리인 Zustand의 핵심 개념과
프로젝트 적용 전략을 분석한다.

---

## 2. 상태관리 라이브러리 비교

| 항목 | Redux Toolkit | Zustand | Recoil | Jotai |
|------|---------------|---------|--------|-------|
| 번들 크기 | ~33KB | ~1.5KB | ~79KB | ~8KB |
| 보일러플레이트 | 많음 (slice, action, reducer) | 최소 | 중간 (atom, selector) | 최소 |
| Provider 필요 | 필수 (`<Provider store>`) | 불필요 | 필수 (`<RecoilRoot>`) | 필수 (`<Provider>`) |
| DevTools | Redux DevTools | Redux DevTools (미들웨어) | 자체 DevTools | 자체 DevTools |
| 러닝 커브 | 높음 | 낮음 | 중간 | 낮음 |
| TypeScript | 좋음 | 매우 좋음 | 보통 | 매우 좋음 |
| 상태 모델 | 중앙 집중 | 중앙 집중 | 원자적 (Atom) | 원자적 (Atom) |
| React 외부 사용 | 불가 | 가능 | 불가 | 불가 |

### Zustand 선택 이유

- **Provider 불필요**: 컴포넌트 트리 어디서든 즉시 사용 가능
- **극소 번들 크기**: 약 1.5KB로 프로젝트 빌드에 부담 없음
- **보일러플레이트 최소화**: store 하나로 상태와 액션을 함께 정의
- **React 외부에서도 호출 가능**: SSE 이벤트 핸들러에서 직접 상태 갱신 가능

## 3. Zustand 핵심 개념

### 3-1. Store 생성

```typescript
import { create } from 'zustand';

interface CounterStore {
  count: number;
  increment: () => void;
  decrement: () => void;
  reset: () => void;
}

const useCounterStore = create<CounterStore>((set) => ({
  count: 0,
  increment: () => set((state) => ({ count: state.count + 1 })),
  decrement: () => set((state) => ({ count: state.count - 1 })),
  reset: () => set({ count: 0 }),
}));
```

- `create` 함수에 상태와 액션을 함께 정의한다
- `set` 함수는 부분 업데이트를 지원한다 (React의 `setState`와 유사)
- 반환값은 React Hook이므로 컴포넌트에서 직접 사용 가능

### 3-2. 컴포넌트에서 사용

```tsx
function Counter() {
  const count = useCounterStore((state) => state.count);
  const increment = useCounterStore((state) => state.increment);

  return (
    <div>
      <span>{count}</span>
      <button onClick={increment}>+1</button>
    </div>
  );
}
```

### 3-3. Selector 패턴

Zustand는 selector를 통해 필요한 상태만 구독한다.
구독하지 않은 상태가 변경되어도 컴포넌트는 리렌더링되지 않는다.

```tsx
// 좋은 패턴: 필요한 상태만 선택
const count = useCounterStore((state) => state.count);

// 나쁜 패턴: 전체 store 구독 (모든 상태 변경 시 리렌더링)
const store = useCounterStore();
```

## 4. 미들웨어

### 4-1. devtools 미들웨어

Redux DevTools와 연동하여 상태 변화를 시각적으로 추적한다.

```typescript
import { create } from 'zustand';
import { devtools } from 'zustand/middleware';

const useLayoutStore = create<LayoutStore>()(
  devtools(
    (set) => ({
      layout: '2x2',
      setLayout: (layout: string) =>
        set({ layout }, false, 'setLayout'),  // 세 번째 인자: 액션 이름
    }),
    { name: 'LayoutStore' }  // DevTools에서 표시될 store 이름
  )
);
```

DevTools에서 확인 가능한 정보:
- 상태 변화 이력 (타임라인)
- 각 액션의 이름과 payload
- 상태 스냅샷 시점 이동 (time-travel debugging)

### 4-2. persist 미들웨어

브라우저 새로고침 후에도 상태를 유지한다. `localStorage` 또는 `sessionStorage`를 사용한다.

```typescript
import { create } from 'zustand';
import { persist, createJSONStorage } from 'zustand/middleware';

interface ThemeStore {
  isDark: boolean;
  toggleTheme: () => void;
}

const useThemeStore = create<ThemeStore>()(
  persist(
    (set) => ({
      isDark: false,
      toggleTheme: () => set((state) => ({ isDark: !state.isDark })),
    }),
    {
      name: 'theme-storage',                          // localStorage key
      storage: createJSONStorage(() => localStorage),  // 저장소 지정
      partialize: (state) => ({ isDark: state.isDark }), // 일부 상태만 영속화
    }
  )
);
```

### 4-3. 미들웨어 조합

여러 미들웨어를 중첩하여 사용할 수 있다.

```typescript
const useLayoutStore = create<LayoutStore>()(
  devtools(
    persist(
      (set) => ({
        layout: '2x2',
        sidebarOpen: true,
        setLayout: (layout) => set({ layout }),
        toggleSidebar: () => set((s) => ({ sidebarOpen: !s.sidebarOpen })),
      }),
      { name: 'layout-storage' }
    ),
    { name: 'LayoutStore' }
  )
);
```

## 5. 프로젝트 적용: layoutStore

CCTV 대시보드의 레이아웃 상태를 관리한다.

```typescript
// src/stores/layoutStore.ts
import { create } from 'zustand';
import { devtools, persist } from 'zustand/middleware';

type LayoutType = '1x1' | '2x2' | '3x3' | '4x4';

interface LayoutStore {
  layout: LayoutType;
  sidebarOpen: boolean;
  selectedCameraId: number | null;
  fullscreenCameraId: number | null;

  setLayout: (layout: LayoutType) => void;
  toggleSidebar: () => void;
  selectCamera: (id: number | null) => void;
  setFullscreen: (id: number | null) => void;
}

export const useLayoutStore = create<LayoutStore>()(
  devtools(
    persist(
      (set) => ({
        layout: '2x2',
        sidebarOpen: true,
        selectedCameraId: null,
        fullscreenCameraId: null,

        setLayout: (layout) =>
          set({ layout }, false, 'setLayout'),
        toggleSidebar: () =>
          set((s) => ({ sidebarOpen: !s.sidebarOpen }), false, 'toggleSidebar'),
        selectCamera: (id) =>
          set({ selectedCameraId: id }, false, 'selectCamera'),
        setFullscreen: (id) =>
          set({ fullscreenCameraId: id }, false, 'setFullscreen'),
      }),
      {
        name: 'layout-storage',
        partialize: (state) => ({
          layout: state.layout,
          sidebarOpen: state.sidebarOpen,
        }),
      }
    ),
    { name: 'LayoutStore' }
  )
);
```

### 컴포넌트에서의 활용

```tsx
// CameraGrid.tsx
function CameraGrid() {
  const layout = useLayoutStore((s) => s.layout);
  const fullscreenId = useLayoutStore((s) => s.fullscreenCameraId);

  const gridClass = {
    '1x1': 'grid-cols-1',
    '2x2': 'grid-cols-2',
    '3x3': 'grid-cols-3',
    '4x4': 'grid-cols-4',
  }[layout];

  if (fullscreenId) {
    return <CameraPlayer cameraId={fullscreenId} fullscreen />;
  }

  return (
    <div className={`grid ${gridClass} gap-2`}>
      {cameras.map((cam) => (
        <CameraPlayer key={cam.id} cameraId={cam.id} />
      ))}
    </div>
  );
}
```

## 6. 프로젝트 적용: weatherStore

외부 날씨 API 데이터를 관리하는 store이다.

```typescript
// src/stores/weatherStore.ts
import { create } from 'zustand';

interface WeatherData {
  temperature: number;
  humidity: number;
  windSpeed: number;
  condition: string;
  updatedAt: string;
}

interface WeatherStore {
  weather: WeatherData | null;
  loading: boolean;
  error: string | null;
  setWeather: (data: WeatherData) => void;
  setLoading: (loading: boolean) => void;
  setError: (error: string | null) => void;
}

export const useWeatherStore = create<WeatherStore>((set) => ({
  weather: null,
  loading: false,
  error: null,
  setWeather: (data) => set({ weather: data, loading: false, error: null }),
  setLoading: (loading) => set({ loading }),
  setError: (error) => set({ error, loading: false }),
}));
```

### React 외부에서 상태 갱신

SSE 이벤트 핸들러 등 React 컴포넌트 외부에서도 상태를 직접 갱신할 수 있다.

```typescript
// SSE 이벤트 리스너 (React 외부)
const eventSource = new EventSource('/api/events');

eventSource.addEventListener('weather', (event) => {
  const data = JSON.parse(event.data);
  // React Hook 없이 직접 store 접근
  useWeatherStore.getState().setWeather(data);
});
```

이 패턴은 Redux에서는 `store.dispatch()`를 사용해야 하지만,
Zustand는 `getState()`로 더 직관적으로 처리할 수 있다.

## 7. React Context API와의 비교

| 항목 | React Context | Zustand |
|------|---------------|---------|
| 리렌더링 | Context 값 변경 시 모든 Consumer 리렌더링 | selector로 구독한 값만 변경 시 리렌더링 |
| Provider | 필수 (트리 상단에 위치) | 불필요 |
| 상태 업데이트 | `useState`/`useReducer` 조합 필요 | `set` 함수 하나로 처리 |
| 비동기 처리 | 직접 구현 | store 내부에서 async/await 사용 가능 |
| 외부 접근 | 불가 | `getState()`, `setState()` 가능 |

### Context의 리렌더링 문제

```tsx
// Context 방식: theme만 변경해도 layout을 구독하는 컴포넌트도 리렌더링됨
const AppContext = createContext({ theme: 'dark', layout: '2x2' });

function Sidebar() {
  const { layout } = useContext(AppContext);  // theme 변경에도 리렌더링 발생
  return <div>{layout}</div>;
}
```

```tsx
// Zustand 방식: layout이 변경될 때만 리렌더링
function Sidebar() {
  const layout = useLayoutStore((s) => s.layout);  // layout 변경 시에만 리렌더링
  return <div>{layout}</div>;
}
```

## 8. 불필요한 리렌더링 방지 패턴

### 8-1. shallow 비교

객체나 배열을 반환하는 selector는 매 렌더링마다 새 참조를 생성한다.
`shallow` 비교를 사용하면 실제 값이 동일할 때 리렌더링을 건너뛸 수 있다.

```typescript
import { useShallow } from 'zustand/react/shallow';

// 여러 값을 한 번에 선택할 때 shallow 비교 적용
function Header() {
  const { layout, sidebarOpen } = useLayoutStore(
    useShallow((s) => ({
      layout: s.layout,
      sidebarOpen: s.sidebarOpen,
    }))
  );

  return <header>{layout} - {sidebarOpen ? 'open' : 'closed'}</header>;
}
```

### 8-2. 액션 분리 선택

액션 함수는 참조가 변하지 않으므로 별도 selector로 분리하면 효율적이다.

```tsx
// 상태와 액션을 분리하여 선택
function LayoutControls() {
  // 액션은 참조 불변 → 이 컴포넌트는 리렌더링 안 됨
  const setLayout = useLayoutStore((s) => s.setLayout);
  const toggleSidebar = useLayoutStore((s) => s.toggleSidebar);

  return (
    <div>
      <button onClick={() => setLayout('2x2')}>2x2</button>
      <button onClick={() => setLayout('3x3')}>3x3</button>
      <button onClick={toggleSidebar}>사이드바 토글</button>
    </div>
  );
}
```

## 9. 정리

- Zustand는 약 1.5KB의 극소 번들 크기로 간결한 상태관리를 제공한다
- `create` 함수 하나로 상태와 액션을 정의하며 Provider가 필요 없다
- selector 패턴을 통해 필요한 상태만 구독하여 불필요한 리렌더링을 방지한다
- `devtools` 미들웨어로 Redux DevTools 연동이 가능하고, `persist`로 localStorage 영속화를 지원한다
- `getState()`를 통해 React 외부(SSE 핸들러 등)에서도 상태에 접근할 수 있다
- 프로젝트에서는 layoutStore(레이아웃/사이드바), weatherStore(날씨 정보) 등으로 관심사를 분리하여 관리한다

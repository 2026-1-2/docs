# 시스템 통합 테스트 전략

## 1. 개요

버티포트 CCTV 감시 시스템은 여러 서비스(프론트엔드, 백엔드, 미디어 서버, 녹화 서버, DB)가 상호작용하는 분산 시스템이다. 각 서비스의 단위 테스트뿐만 아니라 서비스 간 통합 테스트가 중요하다.

---

## 2. 테스트 피라미드

```
        ╱╲
       ╱  ╲        E2E 테스트 (소수)
      ╱    ╲       브라우저 기반 전체 시나리오
     ╱──────╲
    ╱        ╲     통합 테스트 (중간)
   ╱          ╲    API + DB + 외부 서비스
  ╱────────────╲
 ╱              ╲  단위 테스트 (다수)
╱                ╲ 개별 함수/클래스 로직
────────────────────
```

---

## 3. 테스트 범위

### 3-1. 단위 테스트

| 대상 | 테스트 내용 |
|------|-------------|
| AuthService | 로그인 성공/실패, 토큰 생성 검증 |
| CamerasService | CRUD 로직, 유효성 검사 |
| StreamsService | MediaMTX API 호출 로직 |
| EventBusService | 이벤트 발행/구독 |

### 3-2. 통합 테스트

| 대상 | 테스트 내용 |
|------|-------------|
| Auth API | 회원가입 → 로그인 → 토큰으로 보호 API 접근 |
| Camera API | 카메라 등록 → MediaMTX 경로 자동 생성 확인 |
| Stream API | 스트림 목록 조회 → MediaMTX 상태와 일치 확인 |
| Log API | 활동 로그 기록 → 페이지네이션 조회 |

### 3-3. E2E 테스트

| 시나리오 | 테스트 내용 |
|---------|-------------|
| 로그인 → 대시보드 | 로그인 후 카메라 영상 표시 확인 |
| 카메라 추가 | 카메라 등록 → 대시보드에 영상 표시 |
| PTZ 제어 | 방향 버튼 클릭 → 카메라 움직임 확인 |
| 이벤트 알림 | 감지 이벤트 발생 → LiveEventsBar에 표시 |

## 4. NestJS 테스트 프레임워크

### 4-1. Jest 설정

NestJS는 기본적으로 Jest를 테스트 프레임워크로 사용한다.

```bash
# 단위 테스트 실행
npm run test

# 통합(e2e) 테스트 실행
npm run test:e2e

# 커버리지 리포트
npm run test:cov
```

### 4-2. 단위 테스트 예시

```typescript
describe('AuthService', () => {
  let service: AuthService;
  let prisma: PrismaService;

  beforeEach(async () => {
    const module = await Test.createTestingModule({
      providers: [
        AuthService,
        JwtService,
        { provide: PrismaService, useValue: mockPrismaService },
      ],
    }).compile();

    service = module.get<AuthService>(AuthService);
  });

  it('올바른 자격증명으로 로그인 시 토큰을 반환해야 한다', async () => {
    const result = await service.login('admin', 'password');
    expect(result).toHaveProperty('access_token');
  });

  it('잘못된 비밀번호로 로그인 시 예외를 던져야 한다', async () => {
    await expect(service.login('admin', 'wrong')).rejects.toThrow(UnauthorizedException);
  });
});
```

### 4-3. 통합 테스트 예시

```typescript
describe('Camera API (e2e)', () => {
  let app: INestApplication;
  let token: string;

  beforeAll(async () => {
    const module = await Test.createTestingModule({
      imports: [AppModule],
    }).compile();

    app = module.createNestApplication();
    await app.init();

    // 로그인하여 토큰 획득
    const loginRes = await request(app.getHttpServer())
      .post('/auth/login')
      .send({ username: 'admin', password: 'password' });
    token = loginRes.body.access_token;
  });

  it('카메라를 등록하고 조회할 수 있어야 한다', async () => {
    const createRes = await request(app.getHttpServer())
      .post('/cameras')
      .set('Authorization', `Bearer ${token}`)
      .send({
        name: 'Test Camera',
        ipAddress: '192.168.0.101',
        rtspPath: '/Streaming/Channels/101',
        username: 'admin',
        password: 'test',
      });

    expect(createRes.status).toBe(201);
    expect(createRes.body).toHaveProperty('id');

    const listRes = await request(app.getHttpServer())
      .get('/cameras')
      .set('Authorization', `Bearer ${token}`);

    expect(listRes.body).toContainEqual(
      expect.objectContaining({ name: 'Test Camera' }),
    );
  });

  afterAll(async () => {
    await app.close();
  });
});
```

## 5. 테스트 환경 구성

### 5-1. 테스트용 Docker Compose

```yaml
# docker-compose.test.yml
services:
  mysql-test:
    image: mysql:8.0
    environment:
      MYSQL_ROOT_PASSWORD: test
      MYSQL_DATABASE: mmp_test
    ports:
      - "3307:3306"
    tmpfs:
      - /var/lib/mysql   # 메모리에서 실행하여 속도 향상
```

### 5-2. 테스트 환경 변수

```bash
# .env.test
DATABASE_URL=mysql://root:test@localhost:3307/mmp_test
JWT_SECRET=test-secret
```

## 6. CI/CD 통합

```yaml
# .github/workflows/test.yml
jobs:
  test:
    runs-on: ubuntu-latest
    services:
      mysql:
        image: mysql:8.0
        env:
          MYSQL_ROOT_PASSWORD: test
          MYSQL_DATABASE: mmp_test
        ports:
          - 3306:3306
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-node@v4
      - run: npm ci
      - run: npx prisma migrate deploy
      - run: npm run test
      - run: npm run test:e2e
```

## 7. 테스트 커버리지 목표

| 모듈 | 목표 커버리지 | 우선순위 |
|------|-------------|---------|
| auth | 90% | 높음 (보안 관련) |
| cameras | 80% | 높음 (핵심 기능) |
| streams | 70% | 중간 (외부 의존성) |
| logs | 60% | 낮음 |
| system | 50% | 낮음 |

외부 서비스(MediaMTX, 카메라)에 의존하는 부분은 Mock으로 대체하여 테스트 안정성을 확보한다.

# NestJS 서버 아키텍처 설계

## 1. NestJS 선택 이유

| 프레임워크 | 장점 | 단점 |
|------------|------|------|
| Express | 경량, 자유도 높음 | 구조가 없어 대규모 프로젝트에서 코드 관리 어려움 |
| Fastify | 높은 성능 | 생태계가 Express 대비 작음 |
| **NestJS** | **모듈 기반 아키텍처, DI, TypeScript 네이티브** | 러닝 커브 존재 |

NestJS는 Angular에서 영감을 받은 프레임워크로, 모듈-컨트롤러-서비스 패턴을 강제한다.
프로젝트 규모가 커져도 일관된 코드 구조를 유지할 수 있다.

## 3. 핵심 패턴

### 3-1. 의존성 주입 (Dependency Injection)

```typescript
@Injectable()
export class CamerasService {
  constructor(private readonly prisma: PrismaService) {}

  async findAll() {
    return this.prisma.camera.findMany();
  }
}
```

서비스 클래스에 `@Injectable()` 데코레이터를 붙이면 NestJS IoC 컨테이너가 인스턴스를 관리한다. 생성자에서 의존성을 선언하면 자동으로 주입된다.

### 3-2. 모듈 시스템

```typescript
@Module({
  imports: [PrismaModule],
  controllers: [CamerasController],
  providers: [CamerasService],
  exports: [CamerasService],
})
export class CamerasModule {}
```

- `imports`: 다른 모듈의 exported 서비스를 사용
- `controllers`: HTTP 요청을 처리하는 컨트롤러 등록
- `providers`: 비즈니스 로직을 담당하는 서비스 등록
- `exports`: 다른 모듈에서 사용할 수 있도록 서비스 공개

### 3-3. 컨트롤러와 라우팅

```typescript
@Controller('cameras')
export class CamerasController {
  constructor(private readonly camerasService: CamerasService) {}

  @Get()
  findAll() {
    return this.camerasService.findAll();
  }

  @Post()
  create(@Body() createCameraDto: CreateCameraDto) {
    return this.camerasService.create(createCameraDto);
  }

  @Get(':id')
  findOne(@Param('id', ParseIntPipe) id: number) {
    return this.camerasService.findOne(id);
  }

  @Patch(':id')
  update(@Param('id', ParseIntPipe) id: number, @Body() dto: UpdateCameraDto) {
    return this.camerasService.update(id, dto);
  }

  @Delete(':id')
  remove(@Param('id', ParseIntPipe) id: number) {
    return this.camerasService.remove(id);
  }
}
```

## 4. 미들웨어 실행 순서

```
Request
  │
  ▼
Middleware → Guard → Interceptor (before) → Pipe → Controller → Service
                                                       │
  Response ◀── Interceptor (after) ◀── Exception Filter ◀──┘
```

| 계층 | 역할 | 프로젝트 적용 |
|------|------|---------------|
| Guard | 인증/인가 검사 | JwtAuthGuard, RolesGuard |
| Pipe | 입력 데이터 변환/검증 | ParseIntPipe, ValidationPipe |
| Interceptor | 요청/응답 가공 | 로깅, 응답 포맷 변환 |
| Filter | 예외 처리 | HTTP 예외 응답 포맷 통일 |

## 5. Global 설정

```typescript
// main.ts
async function bootstrap() {
  const app = await NestFactory.create(AppModule);

  app.enableCors({
    origin: process.env.CLIENT_URL || 'http://localhost:5173',
  });

  app.useGlobalPipes(new ValidationPipe({
    whitelist: true,       // DTO에 없는 속성 자동 제거
    transform: true,       // 타입 자동 변환
  }));

  await app.listen(3000);
}
```

## 6. 환경 변수 관리

```typescript
// app.module.ts
@Module({
  imports: [
    ConfigModule.forRoot({
      isGlobal: true,
      envFilePath: '.env',
    }),
    // ...
  ],
})
export class AppModule {}
```

`@nestjs/config`의 `ConfigModule`을 사용하여 환경 변수를 중앙에서 관리한다.
`isGlobal: true`로 설정하면 모든 모듈에서 `ConfigService`를 import 없이 사용 가능하다.

## 7. API 문서화 (Swagger)

```typescript
// main.ts
const config = new DocumentBuilder()
  .setTitle('MMP Server API')
  .setVersion('1.0')
  .addBearerAuth()
  .build();
const document = SwaggerModule.createDocument(app, config);
SwaggerModule.setup('api', app, document);
```

`http://localhost:3000/api`에서 Swagger UI를 통해 API 문서를 자동 생성하고 테스트할 수 있다.

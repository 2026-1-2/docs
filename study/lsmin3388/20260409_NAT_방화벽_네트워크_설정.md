# NAT와 방화벽 환경에서의 네트워크 설정

> **작성일**: 2026-04-09

## 1. 개요

버티포트 CCTV 감시 시스템은 Hikvision 카메라 → MediaMTX → 프론트엔드 대시보드까지 영상 스트림이 여러 네트워크 경계를 통과한다. NAT, 방화벽, 가상화 네트워크 설정을 정확히 이해해야 RTSP/WebRTC 스트림이 정상 전달된다.

---

## 2. NAT 종류와 동작 방식

| NAT 유형 | 외부 접근 허용 조건 | WebRTC 연결 난이도 |
|---|---|---|
| **Full Cone** | 내부에서 한 번 매핑되면 모든 외부 호스트가 접근 가능 | 쉬움 |
| **Restricted Cone** | 내부가 먼저 보낸 IP의 호스트만 응답 가능 | 보통 |
| **Port Restricted Cone** | 내부가 먼저 보낸 IP + Port 조합만 응답 가능 | 어려움 |
| **Symmetric** | 목적지마다 다른 외부 포트 매핑, 가장 제한적 | 매우 어려움 (TURN 필수) |

```text
[사설 네트워크]                    [NAT 장비]                   [공인 네트워크]
192.168.1.100:5000  ──────►  203.0.113.1:40000  ──────►  상대방 서버
```

Symmetric NAT에서는 STUN으로 알아낸 공인 IP:Port가 실제 대상에게 전달될 때 달라지므로 **TURN 릴레이 서버가 반드시 필요**하다.

## 3. 포트 포워딩 설정

| 서비스 | 프로토콜 | 내부 포트 | 외부 포트 | 비고 |
|---|---|---|---|---|
| NestJS API | TCP | 3000 | 3000 | REST API |
| MediaMTX RTSP | TCP | 8554 | 8554 | 스트림 수신 |
| MediaMTX WebRTC | TCP/UDP | 8889 | 8889 | 시그널링 |
| MediaMTX HLS | TCP | 8888 | 8888 | HLS 제공 |
| MySQL | TCP | 3306 | - | 외부 노출 금지 |
| TURN 서버 | UDP | 3478 | 3478 | ICE 릴레이 |

```bash
# iptables 포트 포워딩 예시
sudo iptables -t nat -A PREROUTING -p tcp --dport 8889 -j DNAT --to-destination 192.168.1.10:8889
sudo iptables -t nat -A PREROUTING -p udp --dport 8889 -j DNAT --to-destination 192.168.1.10:8889
sudo iptables -t nat -A POSTROUTING -o eth0 -j MASQUERADE
```

## 4. VMware 네트워크 모드

| 모드 | IP 할당 | 호스트 통신 | 외부 통신 | 카메라 직접 접근 |
|---|---|---|---|---|
| **NAT** | VMware DHCP (10.0.x.x) | O (포트 포워딩) | O | X (이중 NAT) |
| **Bridged** | 물리 네트워크 DHCP | O | O | O |
| **Host-Only** | VMware DHCP (192.168.x.x) | O | X | X |

카메라와 같은 서브넷에서 RTSP 수신이 필요하므로 **Bridged 모드**를 사용한다.

## 5. Docker 포트 매핑과 네트워크 드라이버

| 드라이버 | 격리 수준 | 포트 매핑 | 용도 |
|---|---|---|---|
| **bridge** (기본) | 높음 | `-p` 플래그 필요 | 일반적 사용 |
| **host** | 없음 | 불필요 | 성능 중시 |
| **macvlan** | 높음 | 불필요 (고유 MAC) | IoT/카메라 |

```yaml
# docker-compose.yml 핵심 부분
networks:
  vertiport-net:
    driver: bridge
    ipam:
      config:
        - subnet: 172.20.0.0/16

services:
  mediamtx:
    image: bluenviron/mediamtx:latest
    ports:
      - "8554:8554"       # RTSP
      - "8888:8888"       # HLS
      - "8889:8889"       # WebRTC
      - "8189:8189/udp"   # ICE UDP
    networks:
      vertiport-net:
        ipv4_address: 172.20.0.10
  mysql:
    image: mysql:8.0
    ports:
      - "127.0.0.1:3306:3306"  # 로컬만 접근 허용
```

> MySQL은 `127.0.0.1:3306:3306`으로 바인딩하여 외부 접근을 차단한다.

## 6. STUN/TURN 서버의 역할

**STUN**: 클라이언트가 자신의 공인 IP:Port를 알아내는 프로토콜. Full Cone/Restricted Cone NAT에서 효과적.  
**TURN**: Symmetric NAT 등 P2P 불가 시 미디어 트래픽을 릴레이하는 서버.

```bash
# coturn 설정 (/etc/turnserver.conf)
listening-port=3478
realm=vertiport.example.com
lt-cred-mech
user=vertiport:securepassword123
total-quota=100
fingerprint
no-multicast-peers
```

## 7. WebRTC ICE Candidate 흐름

```text
1. Gathering Phase
   ├── Host Candidate:    로컬 IP (192.168.1.5:50000)
   ├── Server Reflexive:  STUN으로 획득한 공인 IP (203.0.113.1:40000)
   └── Relay Candidate:   TURN 서버 할당 IP (198.51.100.1:60000)

2. Connectivity Check → 각 candidate 쌍에 STUN Binding 요청
3. Nomination → 최적 경로 선택 → 미디어 전송 시작
   우선순위: Host > Server Reflexive > Relay
```

```yaml
# mediamtx.yml ICE 서버 지정
webrtcICEServers2:
  - url: stun:stun.l.google.com:19302
  - url: turn:vertiport.example.com:3478
    username: vertiport
    password: securepassword123
```

## 8. UFW 방화벽 규칙 설정

```bash
sudo ufw default deny incoming
sudo ufw default allow outgoing
sudo ufw allow 22/tcp       # SSH
sudo ufw allow 3000/tcp     # NestJS API
sudo ufw allow 8554/tcp     # RTSP
sudo ufw allow 8888/tcp     # HLS
sudo ufw allow 8889/tcp     # WebRTC 시그널링
sudo ufw allow 8189/udp     # WebRTC ICE UDP
sudo ufw allow 3478         # TURN 서버
# MySQL(3306)은 규칙 추가하지 않아 외부 차단
sudo ufw enable
```

## 10. 트러블슈팅 체크리스트

| 증상 | 확인 사항 | 해결 방법 |
|---|---|---|
| WebRTC 연결 실패 | Symmetric NAT 여부 | TURN 서버 구축 |
| RTSP 수신 불가 | 방화벽 8554 차단 여부 | `ufw allow 8554/tcp` |
| Docker 컨테이너 간 통신 실패 | 네트워크 드라이버 | 같은 bridge 네트워크 지정 |
| 외부 API 접근 불가 | 포트 포워딩 누락 | iptables 설정 추가 |
| VM에서 카메라 미발견 | 이중 NAT 발생 | Bridged 모드 전환 |

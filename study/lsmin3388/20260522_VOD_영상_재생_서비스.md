# VOD(Video on Demand) 영상 재생 서비스 설계

## 1. VOD 서비스 개요

VOD(Video on Demand)는 사용자가 원하는 시점의 녹화 영상을 선택하여 재생하는 서비스이다.
실시간 스트리밍과 달리, 이미 저장된 영상 파일을 HTTP 기반으로 제공하므로 안정적인 재생이 가능하다.

버티포트 CCTV 감시 시스템에서 VOD는 다음과 같은 역할을 한다.

| 기능 | 설명 |
|------|------|
| 사후 분석 | 이벤트 발생 시점의 영상을 되돌려 확인 |
| 증거 확보 | 사고/이상 상황의 녹화본을 보존 및 다운로드 |
| 타임라인 탐색 | 날짜/시간 범위를 지정하여 원하는 구간 재생 |
| 다중 카메라 비교 | 동일 시간대 여러 카메라 영상을 동시에 조회 |

## 2. 녹화 파일 관리 구조

### 2-1. 디렉토리 구조 (날짜별/카메라별)

```
/recordings/
├── cam1/
│   ├── 2026-05-20/
│   │   ├── 20260520_090000.mp4
│   │   ├── 20260520_090500.mp4
│   │   └── 20260520_091000.mp4
│   └── 2026-05-21/
│       ├── 20260521_090000.mp4
│       └── ...
├── cam2/
│   ├── 2026-05-20/
│   └── 2026-05-21/
└── cam3/
    └── ...
```

- 카메라 ID를 최상위 디렉토리로 분리하여 각 카메라의 녹화본을 독립 관리한다.
- 날짜별 하위 디렉토리로 구성하여 특정 일자의 파일 탐색 속도를 높인다.
- 파일명에 타임스탬프를 포함하여 정렬만으로 시간순 조회가 가능하다.

### 2-2. 파일 세그먼트 규칙

FFmpeg의 `-segment_time` 옵션으로 5분(300초) 단위로 파일을 분할한다.

```bash
ffmpeg -rtsp_transport tcp \
  -i rtsp://admin:password@192.168.0.101:554/Streaming/Channels/101 \
  -c copy \
  -f segment \
  -segment_time 300 \
  -segment_format mp4 \
  -strftime 1 \
  -reset_timestamps 1 \
  /recordings/cam1/$(date +%Y-%m-%d)/%Y%m%d_%H%M%S.mp4
```

- 5분 단위 분할로 단일 파일 크기를 약 50~100MB로 유지한다.
- 파일 손상 시 해당 세그먼트만 영향을 받으므로 안정성이 높다.

## 3. 녹화 파일 메타데이터 DB 저장

### 3-1. Prisma 스키마

```prisma
model Recording {
  id         Int      @id @default(autoincrement())
  cameraId   Int
  camera     Camera   @relation(fields: [cameraId], references: [id])
  filePath   String   @db.VarChar(500)
  fileName   String   @db.VarChar(200)
  startTime  DateTime
  endTime    DateTime
  duration   Int      // 초 단위
  fileSize   BigInt   // 바이트 단위
  resolution String   @db.VarChar(20) // "1920x1080"
  status     RecordingStatus @default(COMPLETED)
  createdAt  DateTime @default(now())

  @@index([cameraId, startTime])
  @@index([startTime, endTime])
}

enum RecordingStatus {
  RECORDING
  COMPLETED
  CORRUPTED
  DELETED
}
```

### 3-2. 메타데이터 수집 과정

1. FFmpeg 세그먼트 녹화 완료 시 파일 생성 이벤트 감지 (inotify/chokidar)
2. `ffprobe`로 파일의 duration, resolution, codec 정보 추출
3. 파일명에서 시작 시간 파싱, duration을 더하여 종료 시간 계산
4. DB에 메타데이터 INSERT

```typescript
import { execSync } from 'child_process';

function extractMetadata(filePath: string) {
  const output = execSync(
    `ffprobe -v quiet -print_format json -show_format -show_streams "${filePath}"`
  ).toString();
  const info = JSON.parse(output);

  return {
    duration: Math.floor(parseFloat(info.format.duration)),
    fileSize: BigInt(info.format.size),
    resolution: `${info.streams[0].width}x${info.streams[0].height}`,
  };
}
```

## 4. MediaMTX를 통한 HLS VOD 스트리밍

### 4-1. HLS(HTTP Live Streaming) 개요

HLS는 영상을 작은 `.ts` 세그먼트로 분할하고 `.m3u8` 플레이리스트로 관리하는 HTTP 기반 스트리밍 프로토콜이다. 별도의 플러그인 없이 브라우저에서 재생이 가능하다.

### 4-2. VOD용 HLS 변환

녹화된 MP4 파일을 HLS 형식으로 변환하여 제공한다.

```bash
ffmpeg -i /recordings/cam1/2026-05-20/20260520_090000.mp4 \
  -c copy \
  -f hls \
  -hls_time 4 \
  -hls_list_size 0 \
  -hls_segment_filename '/hls/cam1/20260520_090000_%03d.ts' \
  /hls/cam1/20260520_090000.m3u8
```

| 옵션 | 설명 |
|------|------|
| `-hls_time 4` | 4초 단위 세그먼트 분할 |
| `-hls_list_size 0` | 전체 세그먼트를 플레이리스트에 포함 (VOD 모드) |
| `-c copy` | 트랜스코딩 없이 컨테이너만 변환 |

### 4-3. MediaMTX VOD 경로 설정

```yaml
# mediamtx.yml
paths:
  vod/cam1:
    source: publisher
    sourceOnDemand: yes
  vod/cam2:
    source: publisher
    sourceOnDemand: yes
```

HLS 엔드포인트: `http://mediamtx-host:8888/vod/cam1/index.m3u8`

## 5. mmp-server VOD API 설계

### 5-1. API 엔드포인트

| 메서드 | 경로 | 설명 |
|--------|------|------|
| GET | `/api/vod/recordings` | 녹화 파일 목록 조회 (페이지네이션) |
| GET | `/api/vod/recordings/:id` | 특정 녹화 파일 상세 정보 |
| GET | `/api/vod/recordings/:id/stream` | HLS 스트리밍 URL 반환 |
| GET | `/api/vod/search` | 날짜 범위/카메라별 검색 |
| GET | `/api/vod/timeline/:cameraId` | 특정 카메라의 타임라인 데이터 |
| GET | `/api/vod/recordings/:id/download` | 녹화 파일 다운로드 |

### 5-2. 검색 API 쿼리 파라미터

```
GET /api/vod/search?cameraId=1&startDate=2026-05-20T00:00:00&endDate=2026-05-20T23:59:59&page=1&limit=20
```

### 5-3. NestJS 컨트롤러 구현

```typescript
@Controller('api/vod')
export class VodController {
  constructor(private readonly vodService: VodService) {}

  @Get('search')
  async searchRecordings(
    @Query('cameraId', ParseIntPipe) cameraId: number,
    @Query('startDate') startDate: string,
    @Query('endDate') endDate: string,
    @Query('page', new DefaultValuePipe(1), ParseIntPipe) page: number,
    @Query('limit', new DefaultValuePipe(20), ParseIntPipe) limit: number,
  ) {
    return this.vodService.search({
      cameraId,
      startDate: new Date(startDate),
      endDate: new Date(endDate),
      page,
      limit,
    });
  }

  @Get('recordings/:id/stream')
  async getStreamUrl(@Param('id', ParseIntPipe) id: number) {
    const recording = await this.vodService.findOne(id);
    const hlsUrl = await this.vodService.generateHlsUrl(recording);
    return { url: hlsUrl };
  }
}
```


### 6-2. React VOD Player 컴포넌트

```tsx
import React, { useEffect, useRef } from 'react';
import Hls from 'hls.js';

interface VodPlayerProps {
  src: string; // HLS m3u8 URL
}

const VodPlayer: React.FC<VodPlayerProps> = ({ src }) => {
  const videoRef = useRef<HTMLVideoElement>(null);
  const hlsRef = useRef<Hls | null>(null);

  useEffect(() => {
    const video = videoRef.current;
    if (!video) return;

    if (Hls.isSupported()) {
      const hls = new Hls({
        maxBufferLength: 30,
        maxMaxBufferLength: 60,
      });
      hls.loadSource(src);
      hls.attachMedia(video);
      hls.on(Hls.Events.MANIFEST_PARSED, () => {
        video.play().catch(() => {});
      });
      hlsRef.current = hls;
    } else if (video.canPlayType('application/vnd.apple.mpegurl')) {
      video.src = src; // Safari 네이티브 HLS 지원
    }

    return () => {
      hlsRef.current?.destroy();
    };
  }, [src]);

  return (
    <video
      ref={videoRef}
      controls
      style={{ width: '100%', maxHeight: '70vh', background: '#000' }}
    />
  );
};

export default VodPlayer;
```

## 8. 디스크 용량 관리 (자동 삭제 정책)

### 8-1. 용량 산정

| 해상도 | 비트레이트 | 1시간 용량 | 1일 용량 (24h) | 7일 용량 |
|--------|-----------|-----------|---------------|---------|
| 1080p | 4 Mbps | ~1.8 GB | ~43 GB | ~302 GB |
| 1080p | 2 Mbps | ~0.9 GB | ~21 GB | ~151 GB |

카메라 4대 기준, 7일 보관 시 약 600GB~1.2TB의 스토리지가 필요하다.

### 8-2. 자동 삭제 Cron 스크립트

```bash
#!/bin/bash
# cleanup-recordings.sh
# 7일 이전의 녹화 파일을 자동 삭제

RECORDING_DIR="/recordings"
RETENTION_DAYS=7

find "$RECORDING_DIR" -name "*.mp4" -mtime +$RETENTION_DAYS -delete
find "$RECORDING_DIR" -type d -empty -delete

echo "[$(date)] Cleanup completed: removed files older than $RETENTION_DAYS days"
```

```bash
# Crontab 등록 (매일 새벽 3시 실행)
0 3 * * * /opt/scripts/cleanup-recordings.sh >> /var/log/cleanup.log 2>&1
```

### 8-3. 디스크 사용률 기반 긴급 삭제

```typescript
import { execSync } from 'child_process';

function checkDiskUsage(mountPoint: string): number {
  const output = execSync(`df -h ${mountPoint} | tail -1 | awk '{print $5}'`).toString();
  return parseInt(output.replace('%', ''));
}

async function emergencyCleanup(threshold: number = 90) {
  const usage = checkDiskUsage('/recordings');
  if (usage >= threshold) {
    // 가장 오래된 녹화부터 삭제
    const oldest = await prisma.recording.findMany({
      orderBy: { startTime: 'asc' },
      take: 50,
    });
    for (const rec of oldest) {
      fs.unlinkSync(rec.filePath);
      await prisma.recording.update({
        where: { id: rec.id },
        data: { status: 'DELETED' },
      });
    }
  }
}
```

디스크 사용률이 90%를 초과하면 보존 기간과 관계없이 가장 오래된 파일부터 삭제하여 시스템 안정성을 확보한다.

# 시퀀스 다이어그램에서 영상 저장소 레인을 어떻게 나눠야 하는가

## 문제: "영상 저장소" 하나로 뭉쳐놨을 때

처음에 시퀀스 다이어그램을 그릴 때 저장소를 하나의 레인으로 표현했다.

```
[React] [NestJS] [MediaMTX] [영상 저장소]
```

이렇게 그리면 NestJS가 "영상 저장소"에 메타데이터를 조회하는 화살표와,
MediaMTX가 "영상 저장소"에 파일을 저장하는 화살표가 같은 레인을 가리키게 된다.
하지만 이 두 행위는 **완전히 다른 시스템을 대상**으로 한다.

---

## 분리해야 하는 이유

영상 저장소는 물리적으로 두 가지가 존재한다.

| 저장소 | 실제 시스템 | 저장 내용 | 접근 주체 |
|--------|-----------|----------|---------|
| MySQL | 관계형 DB | 녹화 파일 경로, 시작/종료 시각, 카메라 ID | NestJS |
| HDD | 파일시스템 | 실제 .ts/.mp4 파일, 스냅샷 .jpg | MediaMTX, FFmpeg |

이 둘은 인터페이스도 다르고 접근 방식도 다르다.
하나의 레인으로 묶으면 **"누가 무엇에 접근하는지"** 가 다이어그램에서 사라진다.

---

## 올바른 레인 구성

```
[React] [NestJS] [MediaMTX] [MySQL] [HDD]
```

### 각 레인의 역할

**MySQL 레인**
- NestJS가 녹화 시작/종료 메타데이터를 INSERT
- NestJS가 영상 목록 조회 시 SELECT
- HDD 파일의 존재 여부와 별개로 메타데이터만 보관

**HDD 레인**
- MediaMTX가 .ts 세그먼트 파일을 직접 기록
- FFmpeg/OpenCV가 스냅샷 .jpg를 기록
- NestJS는 파일 경로(문자열)만 알고 있고, 실제 파일은 HDD에 있음

---

## 시퀀스 다이어그램 예시: 녹화 영상 조회

```
React          NestJS         MySQL          HDD
  |                |              |             |
  |-- 영상 목록 요청 →|              |             |
  |                |-- SELECT 쿼리 →|             |
  |                |← 파일경로 목록 -|             |
  |← 영상 목록 반환--|              |             |
  |                |              |             |
  |-- 영상 재생 요청 →|              |             |
  |                |              |-- 파일 존재 확인→|
  |                |              |             |← 있음
  |← 스트리밍 URL  --|              |             |
```

NestJS가 MySQL에 쿼리하는 화살표와 HDD에 접근하는 화살표가 명확히 분리된다.

---

## 아키텍처 다이어그램과 용어 일치

아키텍처 다이어그램에서 이미 MySQL과 HDD를 별도 컴포넌트로 표현하고 있다면,
시퀀스 다이어그램의 레인 이름도 동일하게 맞춰야 한다.
다이어그램 간 용어가 다르면 읽는 사람이 이게 같은 시스템인지 다른 시스템인지 헷갈린다.

## 아키텍처: 책임 분리 (Separation of Concerns)

### 핵심 원칙

**영상 바이트 데이터는 MediaMTX가 소유하고, 메타데이터와 비즈니스 로직은 NestJS가 소유한다.**

이는 단순한 모듈 경계가 아니라, *어떤 종류의 데이터를 다루는가*에 기반한 근본적인 책임 분리다.

| 영역 | 담당 | 책임 |
|---|---|---|
| 영상 바이트 데이터 | MediaMTX | RTSP 수신, HLS/WebRTC 변환, 녹화, 스트림 송출 |
| 메타데이터 & 비즈니스 로직 | NestJS (mmp-server) | 카메라 정보, 녹화 이력, 사용자 권한, 트리거 처리 |

### 통신 경로

- **React ↔ MediaMTX**: WebRTC(WHEP) 또는 HLS로 직접 통신 — 영상 스트림은 NestJS를 거치지 않음
- **React ↔ NestJS**: SSE/HTTP로 메타데이터, 상태, 이벤트 통신

**NestJS는 raw 영상 바이트를 한 번도 직접 다루지 않는다.**

### 통합 방식: 트리거 기반의 느슨한 결합

- **NestJS → MediaMTX**: 백엔드가 필요시 MediaMTX API를 호출 (녹화 시작/중지, 스트림 설정 변경 등)
- **MediaMTX → NestJS**: 장애 및 이벤트는 **웹훅(webhook)**으로 전달 — 폴링 방식이 아님

### 이 구조의 장점

- **단일 책임 원칙(SRP)**: MediaMTX는 미디어 프로토콜, NestJS는 비즈니스 로직만 담당
- **성능 격리**: 영상 처리 부하가 API 서버 성능에 영향을 주지 않음
- **장애 격리**: 영상 파이프라인 장애가 메타데이터 API 가용성을 해치지 않음
- **독립적 확장**: MediaMTX와 NestJS를 각각 독립적으로 스케일링 가능

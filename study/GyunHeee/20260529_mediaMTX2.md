## MediaMTX 설치 위치

본 프로젝트에서는 MediaMTX를 별도의 바이너리로 설치하지 않고, **Docker Compose 내 하나의 서비스(컨테이너)**로 구성하여 사내 온프레미스(on-premise) 서버에 배포한다.

### 배포 환경

| 항목 | 내용 |
|---|---|
| 설치 방식 | Docker (공식 이미지 `bluenviron/mediamtx`) |
| 배포 위치 | 회사 온프레미스 로컬 서버 (VPC 내부) |
| 오케스트레이션 | Docker Compose |
| 서비스명 | `media-server` |
| 노출 포트 | `:554` (RTSP) — 필요 시 HLS/WebRTC용 포트(`:8888`, `:8889` 등)도 함께 노출 |
| 네트워크 | mmp-server, video-recorder와 동일한 Docker 내부 네트워크에 속함 |

### docker-compose.yml 구성 예시

```yaml
services:
  media-server:
    image: bluenviron/mediamtx:latest
    container_name: media-server
    restart: unless-stopped
    ports:
      - "554:8554"     # RTSP
      - "8888:8888"     # HLS
      - "8889:8889"     # WebRTC (WHEP)
    volumes:
      - ./mediamtx.yml:/mediamtx.yml
    networks:
      - mmp-network
```

> 위 `ports`/`volumes` 경로는 실제 프로젝트 설정에 맞게 채워 넣어야 한다. (예: `mediamtx.yml` 경로, 컨테이너 내부 RTSP 기본 포트 `8554` → 외부 `554`로 매핑)

### 외부 접근 경로

- 카메라(RTSP) ↔ MediaMTX: VPC 내부 통신, 외부 노출 없음
- 클라이언트(React) ↔ MediaMTX: **Caddy 리버스 프록시**를 통해 `www.360view.co.kr` 하위 경로로 라우팅되어 HTTPS로 접근
- mmp-server ↔ MediaMTX: 같은 Docker 네트워크 내부에서 컨테이너명(`media-server`)으로 통신, REST API(`http://media-server:9997/v3/...`) 호출

### 설정 파일 (`mediamtx.yml`)

MediaMTX의 동작(경로 등록, 인증, 레코딩 정책 등)은 `mediamtx.yml` 설정 파일로 관리되며, 이 파일을 Docker 볼륨으로 컨테이너에 마운트하여 적용한다. 카메라별 경로(`paths`)는 서버 시작 시 또는 mmp-server의 REST API 호출을 통해 동적으로 추가된다.

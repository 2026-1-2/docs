## MediaMTX란?

**MediaMTX**(구 rtsp-simple-server)는 RTSP, RTMP, HLS, WebRTC, SRT 등 다양한 스트리밍 프로토콜을 지원하는 오픈소스 미디어 서버다. 별도의 인코딩 파이프라인을 직접 구현하지 않고도, 하나의 영상 소스를 여러 프로토콜로 동시에 송출(remux/relay)할 수 있도록 설계되어 있다.

### 본 프로젝트에서의 역할

본 시스템에서는 IP 카메라가 송출하는 RTSP 스트림을 수신하여, 다음 두 가지 형태로 변환·중계하는 **media-server** 컴포넌트로 사용한다.

- **HLS**: 웹 클라이언트(hls.js)가 표준 HTTP 요청으로 영상을 재생할 수 있도록 세그먼트(.ts) 및 플레이리스트(.m3u8) 파일을 생성
- **WebRTC (WHEP)**: 저지연 실시간 영상 시청이 필요한 경우 사용

### 도입 이유

기존에는 NestJS 서버 내부에서 `child_process.spawn`으로 FFmpeg 프로세스를 직접 실행하여 RTSP→HLS 변환을 처리했다. 이 방식은 다음과 같은 한계가 있었다.

- 영상 데이터 처리(프로세스 관리, 인코딩)와 비즈니스 로직(API, 인증, DB)이 같은 서버 안에 섞여 있어 책임 분리가 어려움
- FFmpeg 프로세스 장애 발생 시 NestJS 서버 전체에 영향을 줄 수 있는 구조
- 트래픽 증가 시 영상 처리와 API 서버를 독립적으로 확장(scale)하기 어려움

MediaMTX를 별도의 Docker 컨테이너로 분리 도입함으로써, **영상 바이트 데이터 처리는 MediaMTX가, 메타데이터·비즈니스 로직은 NestJS(mmp-server)가 전담**하는 구조로 재설계했다. NestJS는 더 이상 FFmpeg 프로세스를 직접 다루지 않고, MediaMTX의 REST API(`/v3/config/paths/*`)를 호출해 스트림 경로(path)만 제어하는 역할로 축소되었다.

### 사용 포트 / 연동 방식

| 항목 | 내용 |
|---|---|
| 서비스명 | `media-server` (Docker Compose 내) |
| 포트 | `:554` (RTSP) |
| 제어 방식 | mmp-server → MediaMTX REST API 호출 (경로 등록/수정) |
| 장애 감지 | MediaMTX → mmp-server 웹훅(webhook) 알림 |
| 클라이언트 접근 | React(hls.js, WebRTC)가 MediaMTX에 직접 요청 (mmp-server를 경유하지 않음) |

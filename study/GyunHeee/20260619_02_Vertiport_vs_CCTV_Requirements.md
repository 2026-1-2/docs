# 드론 버티포트 환경이 만든 추가 요구사항

## 일반 CCTV 시스템과의 전제 차이

| | 일반 CCTV | 드론 버티포트 CCTV |
|--|----------|-----------------|
| 설치 위치 | 실내 또는 도심 고정 구조물 | 야외 원거리, 옥상, 격오지 |
| 네트워크 | 유선 LAN 안정적 | LTE/5G, 불안정 가능 |
| 목적 | 보안/범죄 억제 | 드론 운용 안전 판단 |
| 영상 외 수집 데이터 | 없음 | 기상, RF 환경, 드론 상태 |
| 시스템 결정 | 사람이 판단 | 자동 판단(is_flyable) 포함 |

---

## 추가 요구사항 1: 네트워크 불안정 대응

유선 네트워크를 당연하게 가정하는 일반 CCTV와 달리,
버티포트는 LTE/5G 연결이 끊기거나 대역폭이 낮은 상황이 발생한다.

**추가된 요구사항**
- 네트워크 끊김 시 로컬에 임시 버퍼 녹화 후 복구 시 동기화
- 저대역폭 환경에서도 동작하는 낮은 해상도 스트림 옵션
- 연결 상태 모니터링 및 재연결 자동화 (MediaMTX 재연결 정책)
- 스트림 중단 이벤트를 "카메라 고장"이 아닌 "네트워크 불안정"으로 구분

```sql
-- stream_interruption_reason ENUM 추가
ALTER TABLE camera_status_logs
ADD COLUMN interruption_reason ENUM('network', 'camera_failure', 'power', 'unknown');
```

---

## 추가 요구사항 2: 원거리 야외 설치

옥외 설치로 인해 직사광선, 역광, 야간 가시성 문제가 일반 실내 CCTV보다 심하다.

**추가된 요구사항**
- 드론 착륙 패드 영역이 화면에 잘 잡히는지 확인하는 카메라 앵글 관리
- 야간 운용 가능 여부 판단을 위한 조도 데이터 연계
- 카메라 렌즈 오염(먼지, 빗물) 감지를 위한 이미지 품질 체크

---

## 추가 요구사항 3: 드론 운용 판단과의 연계

일반 CCTV는 영상을 사람이 보는 것으로 끝나지만,
버티포트 시스템은 CCTV 영상 + 센서 데이터를 종합해서 **자동 운용 가능 여부를 판단**해야 한다.

```
CCTV 영상 (착륙 패드 장애물 확인)
    +
기상 데이터 (풍속, 강수량, 가시거리)
    +
RF 환경 (통신 간섭 여부)
    ↓
is_flyable 판단
```

일반 CCTV에는 없는 **데이터 융합(data fusion)** 요구사항이다.

---

## 추가 요구사항 4: 이벤트 심각도 분류

일반 CCTV는 "움직임 감지" 수준이지만,
버티포트는 드론 안전에 직결되므로 이벤트 심각도가 중요하다.

```sql
CREATE TABLE events (
  severity ENUM('info', 'warning', 'critical') NOT NULL,
  -- critical: 즉시 드론 운용 중단
  -- warning: 운용 가능하나 주의
  -- info: 기록 목적
);
```

`critical` 이벤트는 자동으로 `is_flyable = false`로 전환한다.

---

## 추가 요구사항 5: 원격 관리

현장에 상주 인력이 없는 원거리 버티포트를 원격에서 관리해야 한다.

**추가된 요구사항**
- 웹 UI에서 카메라 PTZ(Pan-Tilt-Zoom) 원격 제어
- 시스템 상태(카메라, 서버, 네트워크) 원격 대시보드
- 이상 발생 시 담당자에게 즉시 알림 (SSE, 푸시 알림)
- 현장 방문 없이 카메라 재부팅, 설정 변경 가능한 원격 관리 API

---

## 요약

드론 버티포트는 일반 CCTV의 **"보여주기"** 기능에 더해,
**"판단하기"** (is_flyable), **"버티기"** (네트워크 불안정 대응), **"원격으로 관리하기"** 세 가지 요구사항이 추가된다.

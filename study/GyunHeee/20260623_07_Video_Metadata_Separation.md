# 영상 바이트 데이터 vs 메타데이터, 책임 분리 원칙

## "왜 NestJS가 영상을 안 만지는가?"

처음엔 직관적으로 이상하게 느껴진다.
NestJS가 백엔드인데 영상 데이터를 다루지 않는다는 게 이상하게 보일 수 있다.

**이유: 경로(path)가 두 개다.**

---

## 이중 경로 구조

```
React ──────────── WebRTC/HLS ────────────→ MediaMTX   (영상 바이트)
React ──────────── SSE/HTTP ──────────────→ NestJS     (메타데이터/이벤트)
```

React는 두 서버와 동시에 통신하지만, 주고받는 데이터의 종류가 완전히 다르다.

| 경로 | 대상 | 데이터 종류 |
|------|------|-----------|
| React ↔ MediaMTX | 스트리밍 서버 | 영상 바이트, 오디오 프레임 |
| React ↔ NestJS | 비즈니스 서버 | 카메라 목록, 알람, 사용자 권한, 이벤트 |

---

## NestJS가 영상을 안 만지는 이유

### 1. 성능
영상 스트림은 초당 수십 MB가 흐를 수 있다.
이걸 NestJS를 경유하면 Node.js가 프록시 역할을 하게 되고, 이벤트 루프가 막힌다.

### 2. 역할 분리
NestJS의 역할은 비즈니스 로직이다.
"어떤 카메라를 볼 수 있는가", "이 사용자는 누구인가", "이 이벤트를 기록해야 하는가" — 이런 판단을 한다.
영상 픽셀을 옮기는 건 NestJS가 판단할 일이 아니다.

### 3. 확장성
MediaMTX는 독립적으로 스케일 아웃할 수 있다.
NestJS가 영상을 중계하면 이 둘의 스케일링이 묶여버린다.

---

## 실제 흐름 예시: 카메라 영상 보기

```
1. React → NestJS: "카메라 목록 주세요" (HTTP)
2. NestJS → React: [{id: 1, name: "정문", streamUrl: "..."}, ...] (HTTP)
3. React → MediaMTX: WebRTC/HLS 연결 (스트리밍 프로토콜)
4. MediaMTX → React: 영상 프레임 전송 (스트리밍)
```

NestJS는 1-2번에만 관여한다. 영상 바이트는 NestJS를 거치지 않는다.

---

## 결론

NestJS는 **"무엇을 볼 수 있는가"** 를 결정한다.  
MediaMTX는 **"어떻게 보여줄 것인가"** 를 담당한다.  
데이터의 종류가 다르기 때문에 경로도 다르고, 각자 최적화된 서버가 처리한다.

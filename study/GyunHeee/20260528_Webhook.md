## 웹훅(Webhook)을 통한 장애 복구

### 웹훅이란?

웹훅은 특정 이벤트가 발생했을 때, 이벤트를 발생시킨 시스템이 미리 등록된 URL로 **직접 HTTP 요청을 보내** 알리는 방식이다. 요청을 받는 쪽이 "무슨 일 있어?"라고 계속 물어보는 폴링(Polling)과 반대로, 이벤트가 일어난 쪽이 "이런 일이 있었어"라고 먼저 알려준다(push 방식).

| 방식 | 동작 | 단점/장점 |
|---|---|---|
| 폴링(Polling) | 클라이언트가 주기적으로 서버 상태를 확인 | 불필요한 요청 발생, 실시간성 떨어짐, 주기가 짧으면 부하 증가 |
| 웹훅(Webhook) | 이벤트 발생 시 서버가 즉시 알림을 push | 실시간성 확보, 불필요한 요청 없음, 이벤트 기반 처리 가능 |

### 본 시스템에서의 적용

MediaMTX는 카메라 연결 실패, 스트림 중단 등의 이벤트가 발생하면 사전에 설정된 NestJS의 엔드포인트로 웹훅 요청을 전송한다. NestJS는 이 요청을 수신하는 전용 API를 통해 장애 상황을 인지하고 다음과 같은 후속 처리를 수행한다.

1. **상태 갱신**: 해당 카메라/스트림의 상태를 DB에 즉시 반영
2. **알림 전파**: SSE를 통해 프론트엔드에 실시간으로 장애 상태 전달
3. **복구 트리거**: 필요 시 MediaMTX에 재연결 요청을 다시 전송

### 웹훅 방식을 선택한 이유

- **즉시성**: 장애 발생과 감지 사이의 지연(latency)을 최소화 — 폴링 주기에 의존하지 않음
- **자원 효율성**: NestJS가 모든 카메라 상태를 주기적으로 조회할 필요가 없어 불필요한 부하가 발생하지 않음
- **책임 분리 원칙과의 일관성**: MediaMTX가 영상 관련 이벤트의 발생 시점을 가장 정확히 알고 있는 주체이므로, 감지의 책임도 MediaMTX에 두고 NestJS는 통지받은 결과만 처리 — 두 시스템 간 역할 경계가 명확하게 유지됨

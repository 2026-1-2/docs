## 시퀀스 다이어그램: 과거 녹화 영상 조회 및 다운로드

본 시퀀스는 관리자가 특정 시점의 녹화 영상을 검색·재생하고, 필요 시 파일을 다운로드하는 전체 흐름을 나타낸다. 참여 객체는 **관리자**, **웹 클라이언트**, **서버(mmp-server)**, **MySQL**, **HDD** 5개이며, "메타데이터는 MySQL, 녹화 파일은 HDD가 담당한다"는 시스템 설계 원칙이 그대로 반영되어 있다.

### ① 영상 목록 조회 (MySQL)

1. 관리자가 조회할 시간 범위를 선택해 과거 영상 조회를 요청한다.
2. 웹 클라이언트가 mmp-server에 영상 목록을 요청한다.
3. mmp-server는 MySQL에 녹화 영상 메타데이터 조회를 질의한다.
4. MySQL은 해당 시간대 녹화의 메타데이터(파일 경로, 녹화 시각, 채널 등)를 반환한다.
5. mmp-server는 이를 가공해 클라이언트에 영상 목록을 전달한다.
6. 클라이언트는 영상 리스트를 화면에 표시한다.

> 이 단계는 HDD(실제 파일)에는 접근하지 않고 MySQL의 메타데이터만으로 처리되어, 응답이 가볍고 빠르다.

### ② 영상 스트리밍 재생 (HDD)

1. 관리자가 목록에서 특정 영상을 선택한다.
2. 웹 클라이언트가 mmp-server에 영상 스트리밍을 요청한다.
3. mmp-server는 ①단계에서 받은 메타데이터의 파일 경로를 기준으로 HDD에 영상 파일을 요청한다.
4. HDD가 영상 데이터를 반환한다.
5. mmp-server는 이를 클라이언트로 스트리밍한다.
6. 클라이언트는 화면에 영상을 재생한다.

> MySQL 조회 결과(경로)가 있어야 HDD 접근이 가능하므로, 두 저장소 간 의존 관계가 명확하게 드러난다. 이 전송은 HLS 세그먼트 방식이 아닌, 저장된 단일 파일을 순차적으로 읽어 보내는 점진적 전송(progressive transfer) 방식이다.

### ③ 파일 다운로드 (HDD)

1. 영상 재생 중 관리자가 다운로드를 요청한다.
2. 웹 클라이언트가 mmp-server에 파일 다운로드를 요청한다.
3. mmp-server는 HDD에 영상 파일을 조회한다.
4. HDD가 파일을 전달한다.
5. mmp-server가 파일을 클라이언트로 전송한다.
6. 클라이언트는 다운로드 완료를 관리자에게 알린다.

> 다운로드와 스트리밍(②)은 동일한 HDD 파일을 대상으로 하지만, 스트리밍은 재생과 동시에 데이터를 점진적으로 전송하고 다운로드는 파일 전체를 로컬에 저장한다는 차이가 있다.

# 프롬프트
> NestJS(Node.js)에서 비동기가 어떻게 작동하는지, async/await과 이벤트 루프의 관계를 설명해줘

## Node.js는 기본적으로 비동기다

Python과 반대로 Node.js(NestJS의 런타임)는 처음부터 비동기로 설계됐다.  
**단일 스레드**지만 I/O 작업을 논블로킹으로 처리해 여러 요청을 동시에 다룬다.

```
┌─────────────────────────────────────┐
│           Node.js 프로세스           │
│                                     │
│  ┌──────────┐    ┌────────────────┐ │
│  │ Call     │    │  이벤트 루프    │ │
│  │ Stack    │◄───│  (Event Loop)  │ │
│  │(한 번에  │    └────────┬───────┘ │
│  │ 하나)    │             │         │
│  └──────────┘    ┌────────▼───────┐ │
│                  │  콜백 큐        │ │
│                  │  (완료된 I/O)   │ │
│                  └────────────────┘ │
│                                     │
│  ┌──────────────────────────────┐   │
│  │  libuv (OS 비동기 I/O 처리)   │   │
│  │  네트워크, 파일, 타이머       │   │
│  └──────────────────────────────┘   │
└─────────────────────────────────────┘
```

네트워크 요청이 들어오면 libuv가 OS에 위임하고, Node.js 메인 스레드는 다른 작업을 계속 처리한다.  
I/O가 완료되면 콜백이 큐에 쌓이고, 이벤트 루프가 순서대로 꺼내 실행한다.

## async/await 동작 방식

```typescript
// NestJS 컨트롤러 예시
@Get(':id')
async findCamera(@Param('id') id: string) {
  // await 지점에서 이벤트 루프에 제어권 반납
  // DB 응답 대기 중 다른 요청 처리 가능
  const camera = await this.prisma.camera.findUnique({ where: { camera_id: +id } });
  return camera;
}
```

**실행 흐름:**

```
요청 A 진입 → await prisma.findUnique() 시작
              ↓ (DB 대기 중 이벤트 루프에 제어권 반납)
요청 B 진입 → await prisma.findUnique() 시작
              ↓ (DB 대기)
요청 A DB 응답 도착 → 콜백 큐 → 재개 → 응답 반환
요청 B DB 응답 도착 → 콜백 큐 → 재개 → 응답 반환
```

스레드를 여러 개 만들지 않아도 수백 개의 요청을 동시에 처리한다.

## NestJS에서 블로킹이 발생하는 경우

`await` 없이 동기 코드가 CPU를 오래 점유하면 이벤트 루프 전체가 멈춘다.

```typescript
// 나쁜 예 — 이벤트 루프 블로킹
@Get('bad')
badEndpoint() {
  // 1초 동안 CPU 점유 → 다른 모든 요청이 1초 대기
  const start = Date.now();
  while (Date.now() - start < 1000) {}
  return 'done';
}

// 좋은 예 — 비동기로 대기
@Get('good')
async goodEndpoint() {
  await new Promise(resolve => setTimeout(resolve, 1000));  // 대기 중 다른 요청 처리 가능
  return 'done';
}
```

**alertStream을 NestJS에서 구독할 때의 문제:**  
`axios`로 스트리밍 GET 요청을 날리면 이 자체는 논블로킹이다.  
하지만 multipart 스트림을 줄 단위로 파싱하는 루프는 이벤트 루프를 조금씩 점유한다.  
`OnModuleInit`에서 백그라운드로 실행하되, 파싱 로직은 가볍게 유지해야 한다.

## Promise와 Observable 차이 (NestJS 맥락)

NestJS는 두 가지 비동기 패턴을 모두 지원한다.

| | Promise | Observable (RxJS) |
|---|---|---|
| 값 개수 | 1개 | 0개 ~ 무한 |
| 취소 | 불가 | 가능 (`unsubscribe()`) |
| 적합한 상황 | DB 조회, HTTP 요청 | 스트림, WebSocket, 이벤트 |
| 사용 예 | `async/await` | `from(stream).pipe(...)` |

```typescript
// Promise — DB 조회 (1번 응답)
const camera = await this.prisma.camera.findUnique(...);

// Observable — 이벤트 스트림 (계속 흐름)
import { fromEvent } from 'rxjs';
fromEvent(emitter, 'alert').pipe(
  filter(e => e.type === 'fielddetection'),
).subscribe(e => this.emailService.send(e));
```

alertStream처럼 계속 데이터가 흘러오는 경우엔 Observable이 더 어울리지만,  
단순 구현이라면 `async` 루프로도 충분하다.

## NestJS 생명주기와 비동기 초기화

```typescript
@Injectable()
export class AlertsService implements OnModuleInit {
  onModuleInit() {
    // 앱 시작 시 자동 호출
    // alertStream 구독 시작 위치
    this.startListening();  // await 없이 백그라운드 실행
  }

  private async startListening() {
    // 이 함수는 await 없이 실행돼 백그라운드에서 돈다
    while (true) {
      try {
        await this.subscribeToStream();
      } catch {
        await new Promise(r => setTimeout(r, 10000));  // 10초 후 재연결
      }
    }
  }
}
```

## 핵심 정리

| 개념 | Python threading | Node.js 이벤트 루프 |
|------|-----------------|-------------------|
| 동시성 방식 | OS 스레드 교체 | 단일 스레드 + 콜백 큐 |
| I/O 대기 중 | 다른 스레드 실행 | 이벤트 루프가 다른 콜백 처리 |
| CPU 작업 | 스레드별 GIL 경쟁 | 이벤트 루프 블로킹 위험 |
| 코드 스타일 | 동기 코드 그대로 사용 가능 | async/await 또는 콜백 필요 |

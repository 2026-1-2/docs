# 프롬프트
> Python에서 동기/비동기가 어떻게 작동하는지, threading과 asyncio의 차이는 무엇인지 설명해줘

## Python은 기본적으로 동기다

Python 코드는 위에서 아래로 한 줄씩 순서대로 실행된다.  
함수 하나가 끝나야 다음 함수가 시작된다.

```python
def fetch():
    resp = requests.get('http://camera/stream')  # 여기서 블로킹 — 응답 올 때까지 멈춤
    print(resp.status_code)                       # fetch() 끝나야 실행

fetch()
print('이 줄은 fetch()가 완전히 끝난 뒤에 실행됨')
```

`requests.get(stream=True)`로 alertStream을 구독하면, 그 줄에서 프로세스 전체가 멈춘다.  
다른 카메라를 동시에 구독하려면 별도 전략이 필요하다.

---

## 동시성을 얻는 방법 3가지

### 1. threading — 스레드 (I/O 대기에 적합)

```python
import threading
import requests

def listen(camera_ip):
    resp = requests.get(f'http://{camera_ip}/stream', stream=True)
    for line in resp.iter_lines():
        print(line)

t1 = threading.Thread(target=listen, args=('192.168.0.101',))
t2 = threading.Thread(target=listen, args=('192.168.0.102',))
t1.start()
t2.start()
# 두 카메라가 동시에 실행됨
```

**특징:**
- OS가 스레드를 교체하며 실행 (선점형)
- I/O 대기(네트워크, 파일) 중엔 다른 스레드가 실행됨
- Python GIL(전역 인터프리터 잠금) 때문에 CPU 연산은 진짜 병렬이 아님
- alertStream처럼 I/O 위주 작업엔 threading이 충분하고 적합

### 2. asyncio — 이벤트 루프 (단일 스레드 비동기)

```python
import asyncio
import aiohttp

async def listen(camera_ip):
    async with aiohttp.ClientSession() as session:
        async with session.get(f'http://{camera_ip}/stream') as resp:
            async for line in resp.content:
                print(line)

async def main():
    await asyncio.gather(
        listen('192.168.0.101'),
        listen('192.168.0.102'),
    )

asyncio.run(main())
```

**특징:**
- 스레드 없이 단일 스레드에서 동시성 구현
- `await` 지점에서만 다른 코루틴으로 전환 (협력형)
- `requests`는 asyncio와 호환 안 됨 → `aiohttp` 같은 비동기 라이브러리 필요
- 더 효율적이지만 코드 전체가 `async/await`으로 통일돼야 함

### 3. multiprocessing — 프로세스 (CPU 연산에 적합)

```python
from multiprocessing import Process

def listen(camera_ip):
    ...  # 별도 프로세스에서 실행

p = Process(target=listen, args=('192.168.0.101',))
p.start()
```

**특징:**
- GIL 영향 없음 → CPU 집약 작업(이미지 처리 등)에 적합
- 메모리 공유가 안 돼 프로세스 간 통신(Queue, Pipe)이 필요
- alertStream 구독엔 과도한 선택

---

## 어떤 걸 써야 할까

| 상황 | 선택 |
|------|------|
| 카메라 여러 대 alertStream 동시 구독 | `threading` |
| 전체 코드를 비동기로 짤 수 있을 때 | `asyncio` + `aiohttp` |
| 이미지 분석 등 CPU 작업 추가 시 | `threading` + `concurrent.futures` |

**현재 video-recorder 프로젝트 구조 기준**: 이미 `threading.Thread` 기반 루프가 있으므로  
alertStream 리스너도 `threading.Thread`로 추가하는 게 가장 자연스럽다.

## 핵심 개념 정리

| 개념 | 의미 |
|------|------|
| 블로킹(Blocking) | 작업이 끝날 때까지 다음 코드가 실행 안 됨 |
| 논블로킹(Non-blocking) | 작업을 시작만 하고 바로 다음 코드로 넘어감 |
| 동시성(Concurrency) | 여러 작업을 번갈아 처리 (threading, asyncio) |
| 병렬성(Parallelism) | 여러 작업을 진짜로 동시에 처리 (multiprocessing) |
| GIL | Python이 한 번에 한 스레드만 바이트코드 실행하도록 제한하는 잠금 장치 |

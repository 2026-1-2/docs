# 메인 대시보드 레이아웃 및 관제 UI 개선 정리

## 1. 개선 배경

메인 대시보드는 52인치급 16:9 관제 모니터에서 스크롤 없이 CCTV 상태와 핵심 운영 정보를 빠르게 파악하는 화면이어야 한다.

기존 화면은 Dockview 패널 이동/삭제 기능, 미연결 버튼, 과한 상태 표시, mock 기반 지표가 함께 노출되어 관제 화면의 목적이 흐려지는 문제가 있었다.

따라서 이번 개선은 다음 기준으로 진행했다.

- 관제자가 실제로 확인해야 하는 정보만 남긴다.
- 화면을 고정 레이아웃으로 유지한다.
- CCTV 영역을 가장 큰 비중으로 배치한다.
- PTZ, 날씨, 이벤트처럼 관제에 필요한 조작/상태 정보만 우측 패널과 하단 이벤트 영역에 정리한다.
- 아직 실제 데이터가 아닌 값은 mock임을 인지하고 후속 연동 대상으로 분리한다.

---

## 2. 레이아웃 고정

Dockview를 사용하지만 사용자가 패널을 자유롭게 이동하거나 삭제하지 못하도록 조작 기능을 잠갔다.

적용 내용은 다음과 같다.

- Dockview drag and drop 비활성화
- floating group 비활성화
- tab overflow 비활성화
- 패널 header/tab 제거
- close 버튼 제거
- 저장된 layout state 제거
- 기본 레이아웃만 사용

이로 인해 대시보드는 매번 동일한 화면 구조로 렌더링된다.

```text
┌───────────────────────────────┬──────────────┐
│ CCTV Wall                     │ Telemetry    │
│                               │ Weather      │
│                               │ Network      │
│                               │ PTZ Control  │
├───────────────────────────────┴──────────────┤
│ Live Events                                  │
└──────────────────────────────────────────────┘
```

---

## 3. Sidebar 및 Header 정리

좌측 사이드바는 관제 화면에서 너무 큰 비율을 차지하지 않도록 축소했다.

변경 내용은 다음과 같다.

- sidebar 폭을 72px로 축소
- 회사 로고 추가
- 상단 live 표시 제거
- 좌측 하단 Admin 아이콘 제거
- nav label은 화면에 직접 노출하지 않고 icon 중심으로 정리

Header에서는 서비스에 존재하지 않는 알림 기능을 제거했다.

- 우측 상단 알림 아이콘 제거
- 사용자 프로필 아이콘만 유지
- 현재 시각, 날짜, LIVE 상태 표시 유지

---

## 4. CCTV Wall 개선

CCTV Wall은 메인 대시보드에서 가장 중요한 영역이므로 가장 큰 공간을 유지한다.

변경 내용은 다음과 같다.

- CCTV 개수에 따라 grid column/row 자동 조정
- dev tool로 1, 2, 4, 6, 8, 10개 카메라 레이아웃 확인 가능
- dev tool은 기본 접힘 상태로 변경
- CCTV 1개일 때 화면이 과하게 커져 UI가 잘리는 문제 수정
- CCTV 카드 모서리에 보이던 scale/focus 표시 제거
- PTZ 가능 카메라에는 작은 PTZ badge만 표시
- CCTV 카드 하단의 미니 PTZ 컨트롤 제거

CCTV 카드를 클릭하면 해당 카메라가 선택되고, 선택된 카메라는 accent ring으로 구분된다.

## 5. PTZ Control 구조

처음에는 PTZ 가능 카메라 카드 하단에 작은 PTZ 컨트롤을 넣었지만, 화면이 복잡해지고 어떤 카메라를 조작하는지 명확하지 않았다.

최종 구조는 다음과 같다.

- CCTV 카드를 클릭하면 `selectedCamera` 상태가 변경된다.
- 우측 하단 `PTZ CONTROL` 패널은 선택된 CCTV를 조작 대상으로 사용한다.
- 선택된 CCTV의 이름과 모델을 PTZ 패널에 표시한다.
- PTZ 지원 카메라를 선택하면 `ACTIVE` 상태로 조작 가능하다.
- PTZ 미지원 카메라를 선택하면 `UNAVAILABLE` 상태와 안내 문구를 표시한다.

이 구조는 조작 대상이 명확하고, CCTV 화면 위에 조작 UI가 겹치지 않는 장점이 있다.

## 6. Weather / Telemetry 개선

기존 Telemetry 영역의 날씨 정보는 mock 데이터였다.

이번 개선에서는 백엔드 weather API를 기다리지 않고, CCTV 설치 지점의 고정 좌표를 기반으로 프론트에서 외부 날씨 데이터를 조회하도록 변경했다.

사용 좌표는 다음과 같다.

```ts
export const CCTV_WEATHER_LOCATION = {
  label: '대구 북구 원대로 123',
  latitude: 35.888462,
  longitude: 128.58263,
};
```

현재는 Open-Meteo API를 사용한다.

가져오는 정보는 다음과 같다.

- 풍속
- 풍향
- 온도
- 습도
- 순간 풍속
- 날씨 코드
- 관측 시각

풍속 상태는 프론트에서 임계값 기준으로 계산한다.

```ts
normal  = 7m/s 미만
caution = 7m/s 이상
 danger = 10m/s 이상
```

화면에는 다음 정보를 표시한다.

- 풍속 상태
- 풍향
- 온도 / 습도
- 날씨
- 관측 시각
- 화면 갱신 시각

`관측 시각`은 외부 날씨 데이터가 기준으로 삼는 시각이고, `화면 갱신`은 프론트가 데이터를 다시 가져온 시각이다.

---

## 7. 날씨 새로고침과 Live Events

프론트가 외부 날씨 API를 직접 조회하는 구조에서는 SSE나 WebSocket을 붙여도 실시간 이벤트 효과가 크지 않다.

백엔드가 날씨 데이터를 계속 감시하지 않기 때문에, 프론트는 fetch 이후에야 풍속 상태 변화를 알 수 있다.

따라서 현재 구조는 다음 방식으로 정리했다.

- 날씨 데이터는 5분 주기로 자동 refetch
- 날씨 섹션에 수동 새로고침 버튼 제공
- 새 데이터를 가져온 뒤 이전 `riskLevel`과 비교
- 풍속 단계가 바뀐 경우에만 Live Events에 `Wind Alert` 추가
- 기존 mock Weather Sensor 이벤트 제거

즉 Live Events의 날씨 이벤트는 실제 상태 변화가 감지되었을 때만 추가된다.

## 8. 네트워크 대역폭 상태

현재 `네트워크 대역폭`은 실제 네트워크 감지 값이 아니다.

현재 값은 카메라 개수 기반 mock 계산이다.

```ts
const bandwidth = cameraCount * 4.7;
```

따라서 이 영역은 후속 연동이 필요하다.

가능한 방향은 다음과 같다.

1. 현재 화면에 표시 중인 CCTV stream bitrate 합산
2. `/streams/active` 기반 활성 스트림 대역폭 집계
3. MediaMTX 또는 서버 metrics 기반 실제 outbound traffic 표시
4. 현장 스위치/SNMP 기반 네트워크 장비 트래픽 표시

현재 단계에서는 `네트워크 대역폭`보다 `라이브 스트림 대역폭`이라는 라벨이 더 정확하다.

## 9. 제거한 UI

이번 개선에서 제거한 UI는 다음과 같다.

- Dockview panel header/tab
- 패널 close 버튼
- 패널 이동/분리 기능
- 저장된 dashboard layout state
- Camera OPS 패널
- PoE Power 패널
- CCTV 카드 하단 미니 PTZ 컨트롤
- CCTV 카드 모서리 scale/focus 표시
- Header 알림 아이콘
- Sidebar 하단 Admin 아이콘
- 메인 대시보드의 불필요한 toggle UI

---

## 10. 남은 작업

후속 작업으로 분리해야 할 내용은 다음과 같다.

- 실제 카메라 목록 API 기반 CCTV Wall 구성
- 라이브 스트림 세션 API 기반 WebRTC/HLS 연결
- PTZ API 실제 카메라 ID와 매핑
- Weather API 실패/쿨다운 정책 세부 조정
- Live Events를 mock이 아닌 실제 이벤트 store/API 기반으로 전환
- 네트워크 대역폭 mock 제거 및 실제 stream/network metrics 연동
- 로그인/JWT 인증 이후 권한별 UI 제어

---

## 11. 정리

이번 메인 대시보드 개선의 핵심은 관제 화면의 목적을 명확히 하는 것이다.

CCTV 화면을 중심으로 고정 레이아웃을 만들고, 오른쪽에는 날씨/네트워크/PTZ처럼 관제자가 판단하거나 조작해야 하는 정보만 남겼다.

아직 일부 지표는 mock 또는 프론트 계산값이지만, 어떤 값이 실제 데이터이고 어떤 값이 후속 연동 대상인지 구분할 수 있는 구조로 정리했다.
